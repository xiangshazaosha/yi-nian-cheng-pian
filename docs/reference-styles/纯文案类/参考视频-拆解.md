# 参考视频拆解：参考视频.mp4

> 视频源：`参考视频/参考视频.mp4`  
> 主风格：**纯文案类**  
> 次要特征：企业研究报告 / 数据解释 / UI 证据卡 / 编辑式排版  
> 分析范围：完整视频；抽帧位置只用于覆盖性复核，不作为拆解索引。

## 一、风格身份证

### 分类结论

本片归入**纯文案类**主体叙事由标题、短句、卡片、流程节点、数字和表格排版完成。GitHub 截图、代码框和 Excel 模型只是论据，不承担连续操作演示，因此不归入屏幕演示类，也不归入混合叙事类。

### 一句话风格

黑 / 暖白双主题的企业研究报告式 motion graphics：高密度但分批揭示，使用皇家蓝作为品牌锚点，以斜切蓝色擦除统一换章。

### 风格边界

- **必须保留**：文字主叙事、黑与暖白交替、蓝色结构强调、卡片分批出现、证据链式表达、统一斜切转场。
- **可以替换**：金融主题词、GitHub / Excel 截图、具体表格内容、页眉品牌小字。
- **不要混入**：星空辉光、霓虹黄绿标签、拟物手机框、大量实拍素材；这些会把本片从克制的报告风拉向另一套包装。

## 二、视频基础信息

- 容器：MP4
- 画面：1920 × 1080，30 fps，H.264，16:9
- 时长：125.2 秒
- 音频：AAC，44.1 kHz，双声道；音频流约 123.26 秒
- 主要底色：近黑 `#0E1215`、暖白 `#F4F1E8`
- 品牌蓝：约 `#2F54D6`
- 辅助色：浅蓝灰卡、红色错误标签、黑白高对比文字
- 字体气质：粗黑无衬线标题 + 常规无衬线正文 / 标注；数字使用超大字号制造章节锚点

## 三、语义任务 × 使用环境

> 下表回答“什么内容应该调用什么画面”，而不是复述原片先后顺序。同一语义可按新片内容长度伸缩。

| 语义任务 | 触发语义 | 使用环境 | 画面职责与推荐递进 |
| --- | --- | --- | --- |
| 开场钩子 | 复杂、反常识、数量巨大、终于有人解决等强判断 | 知识解释、工具介绍、商业研究片开头；需要迅速建立问题规模 | 暗底大标题先给结论，标签矩阵补充范围，超大数字或叠卡最后证明规模；第一眼只读主判断 |
| 栏目或主题定位 | “这一期讲什么”“属于哪个专题”“资料在哪里” | 钩子之后、章节开始或系列内容建立固定认知时 | 大面积留白承载一句栏目承诺，分类标签和资料提示后补；不与证据表格同屏 |
| 来源背书 | 官方来源、公开项目、Star 数、数据出处、权威机构 | 观众可能质疑真实性，需要先建立可信度 | 证据截图居中，先展示全貌，再只框选一个关键数字或来源名称；包装不能遮住原始证据 |
| 规模与分类概览 | 数量很多、包含多种模块、需要先看全貌 | 产品能力盘点、课程目录、工具集合、方案总览 | 左侧超大数字负责规模，右侧卡片轮播负责分类；进度标记帮助理解“正在看哪一类” |
| 痛点与风险罗列 | 没有来源、对不上、硬编码、报错、不可追溯 | 提出问题、审计失败、旧方法缺陷；情绪应明确但不娱乐化 | 暖白工作纸建立业务环境，错误便签逐项贴入；红色只留给最高风险，其余问题保持中性 |
| 方法与专业标准 | “真正缺的是”“正确流程是”“必须依次完成” | 从问题转入方法论、解释标准流程或建立判断框架 | 标题先改写问题，流程节点按因果顺序出现，连线在节点就位后补齐；重点是逻辑链而非装饰 |
| 规则如何影响结果 | 公式约束、输入变化、结果更新、机制证明 | 需要证明规则不是口号，而会改变可观察结果 | 左侧放规则或代码，右侧放业务结果；先建立对应关系，再替换关键数值，单位与来源始终保留 |
| 分阶段确认 | 不能一次做完、需要人工确认、每步审核后再继续 | 多步骤建模、审批、质检、教程和治理流程 | 检查卡先给全貌，再逐项从待确认变为确认；已确认项常驻，让观众看到累积进度 |
| 审计与风险分级 | 发现多个问题，需要区分严重程度和处理顺序 | 合规、审计、质量检查、诊断报告 | 表格先建立字段，问题行逐步填入，Critical / Warning / Info 用有限色彩分级，最后补处理流程 |
| Before / After 价值证明 | 同一输入、同一任务，只改变方法或工具 | 产品价值、方案对比、案例证明；必须保证比较条件一致 | Before 保持低饱和，After 用品牌蓝建立结论区；顶部先声明控制变量，随后揭示证据链 |
| 验证标准总结 | “只看这几件事”“是否满足四项条件” | 长解释后的检查清单、购买判断、复盘标准 | 2×2 或 2×3 卡片网格先完整出现，再按口播逐项打勾；适合名词短语，不适合长段正文 |
| 结论收束 | “不是 X，而是 Y”“真正有意义的是” | 观点反转、核心价值回收、进入结尾前 | 暗底左侧两行结论，右侧用阶梯流程重述逻辑，底部能力标签最后出现；不再引入新论据 |
| 受众筛选与免责声明 | 谁适合、谁不适合、适用岗位、风险提示 | CTA、教育内容结尾、专业或金融题材的边界说明 | 暖白卡片列出受众，最后用独立红色提示条声明限制；CTA 与风险说明不可混成同一级强调 |

本风格的语义组织通常遵循“判断 → 证据 → 问题 → 方法 → 验证 → 结论”，但新片应按内容需要选用，不必照搬原片数量或顺序。每个信息页只表达一个判断，相关证据和卡片按理解顺序分批揭示，避免一次性塞满。

## 四、主构图模式库

### 1. 编辑式标题页

- 标题位于左上安全区，通常占画面宽 30-55%，保持大面积留白。
- 右上固定极小页眉“ANTHROPIC · FINANCIAL SERVICES”，形成报告页编号感。
- 适合开场、章节、结论；单页只保留一个主判断和 0-3 个辅助标签。
- 暗底用白字，暖白底用近黑字；关键词才用蓝色，不做整句彩色。

### 2. 左锚点 + 右证据区

- 左侧用超大数字、标题或短句做视觉锚点，右侧放卡片组、轮播或流程。
- 左右权重约 30:70；中线附近留出明显呼吸区。
- 适合“规模 + 明细”“观点 + 证据”“结论 + 方法链”。
- 右侧证据分批出现，不与左侧标题争抢第一眼。

### 3. 报告页卡片网格

- 暖白底，顶部左对齐标题和一行小字，主体使用 2×2、2×3 或 1×4 卡片阵列。
- 卡片以细描边、浅蓝填充、编号、勾选状态组织信息。
- 适合步骤、检查项、受众、条件；单卡只放一个名词或短语。
- 同屏最多六卡，依靠状态变化讲顺序，不依靠长正文。

### 4. 全宽证据表 / 截图

- 证据对象占画面宽约 74-96%，居中或左对齐；标题保留在其上方。
- GitHub 截图、审计表、Excel 网格和代码框都按“证据卡”处理，不模拟完整操作过程。
- 使用描边框、局部色块或数值变化标注重点；每次只强调一个区域。

### 5. Before / After 对比页

- 左右等分或 40:60；Before 保持低饱和和稀疏，After 使用整块品牌蓝。
- 顶部小条写清比较条件，避免只靠颜色暗示结论。
- 适合价值证明；不适合比较超过两组对象。

## 五、内容组件库

### 1. 报告式大标题

- 约 64-92px，粗黑无衬线，左对齐，1-2 行。
- 单个关键词可改为品牌蓝，形成语义重音。
- 入场用 6-12 帧淡入或短距离上移；不使用弹簧夸张回弹。

### 2. 微型页眉 / 分类标签

- 右上或标题上方，约 12-18px，全大写或高字间距。
- 只承担品牌、栏目和上下文，不承担正文。
- 全片常驻同一位置，是视觉一致性的主要来源之一。

### 3. 编号卡 / 检查卡

- 左上角小编号，主体为 2-6 字短语，右侧可出现确认、待确认或勾选。
- 默认白 / 浅蓝底、深色细框；激活时蓝色描边和蓝色勾选。
- 同组逐张出现或逐张改变状态，间隔约 12-30 帧。

### 4. 错误便签

- 红 / 白小卡，轻微旋转 1-3°，黑色细描边和向右下偏移的硬阴影。
- 用于问题罗列；单屏 3-4 张，位置错落但不重叠正文。
- 入场为短距离滑入 + 微旋转归位，强调“贴上去”的动作。

### 5. 流程节点与箭头

- 3-5 个矩形节点，文本 2-4 字，水平或阶梯排列。
- 节点先出现，箭头 / 连线随后补齐；当前节点可使用浅蓝底。
- 主要表达可追溯顺序，不做复杂流程图。

### 6. 证据框

- 截图、代码、表格、数据卡统一放入细边框矩形。
- 高亮以蓝色矩形描边或局部色块完成，不加辉光。
- 证据对象保持清晰可读，外围包装不得覆盖原始关键信息。

### 7. 底部口播字幕

- 黑色高不透明圆角底 + 白字，水平居中，位于底部安全区。
- 1 行为主，按句切换，不做逐字彩色卡拉 OK。
- 字幕是辅助理解，不改变“纯文案类”判定；主画面即使去掉字幕仍能读懂结构。

## 六、视觉处理模块库

### 1. 黑 / 暖白双主题

- 近黑页用于钩子、证据、审计和结论，气质更技术、更强势。
- 暖白页用于解释、步骤、对比和受众，气质更像研究报告。
- 主题通常在章节转场后整体切换，不在同一页做渐变融合。

### 2. 品牌蓝结构层

- 皇家蓝约 `#2F54D6`，用于下划线、关键词、卡片激活态、After 面板和转场。
- 蓝色负责“结构”和“结论”，面积不超过页面主体的约三分之一；只有转场允许全屏蓝。

### 3. 细描边 + 硬阴影

- 卡片常用 1-2px 深色描边，阴影为小幅右下偏移，模糊很少。
- 与现有包装库的霓虹外发光不同，不能直接套用高辉光配方。

### 4. 轻微倾斜与叠纸

- 便签、技能卡和编号封面使用 1-4° 旋转、错位叠放和透视扇形。
- 只在强调对象上使用；常规正文和表格保持正直。

### 5. 网格纸 / 报告纸肌理

- Excel 痛点页使用极浅网格；其余暖白页接近纯色纸张。
- 纹理对比度极低，只建立语境，不能抢文字。

## 七、动效与转场模块库

### 1. 斜切品牌蓝擦除

- 每个主要段落统一使用；皇家蓝面板带斜边和窄白分隔线横向扫过。
- 从旧画面到全蓝再到新画面，约 0.5-0.8 秒（15-24 帧）。
- 作用是换章而非炫技；全片保持同方向和同速度，不混用淡化、缩放等其他主转场。

### 2. 卡片顺序揭示

- 同组卡片每隔约 0.4-1.0 秒出现一张或切换一次状态。
- 入场以 opacity + 8-24px 位移为主，缓动偏克制 ease-out。
- 与口播枚举项同步；已经出现的卡片保持常驻，必要时由浅灰转蓝表示确认。

### 3. 横向面板揭示

- 用于 GitHub 截图、Before / After 右侧面板和证据区。
- 通过裁切宽度或蓝色面板从右侧进入，约 12-24 帧完成。
- 不使用 3D 翻转，保持企业演示的平面感。

### 4. 3D 卡片轮播

- 仅用于“55 个 Skill”规模展示；中心卡正面，两侧卡以 Y 轴旋转形成扇形。
- 每讲到一个 Skill 横向换位一次，左侧序号同步更新。
- 属于本片少数高动感模块，不宜复制到每个段落。

### 5. 数值替换

- 财务示例中 5.0%→6.5%、¥124M→¥136M 直接替换或短淡化，证明公式是活的。
- 数值变化必须保留单位和公式来源，避免只做无语义滚动数字。

### 6. 流程逐节点生长

- 节点按语义顺序出现，连接箭头在相邻节点就位后补上。
- 水平流程和阶梯流程使用同一时序语法，形成跨页面一致性。

## 八、典型组合配方

### 配方 A：一句结论 + 五步方法

- 暖白报告页；左上两行大标题，关键词蓝色。
- 下方五节点水平流程，节点逐个出现，箭头随后连接。
- 底部保留口播字幕；其余区域留白。

### 配方 B：问题清单

- 暖白网格底模拟工作表。
- 3-4 张错误便签错落贴入，红色只给最高风险项。
- 便签分批出现并轻微旋转，不另加大段解释文字。

### 配方 C：证据对比

- 暖白左右分栏，顶部窄条写明同数据 / 同任务 / 唯一变量。
- 左侧 Before 低饱和，右侧 After 使用整块品牌蓝。
- After 面板横向揭示，内部四项证据依次打勾。

### 配方 D：暗底结论页

- 左侧白色两行结论，右侧阶梯流程。
- 底部三个短标签依次出现，蓝色只标当前核心能力。
- 通过蓝色斜切转场进入暖白 CTA 页。

### 建议的风格专属组件候选

以下是扒片候选，不自动加入共享包装库；若要实现，先走 `docs/packaging-library/extension-rules.md`：

5. `StickyProblemCard`：轻旋转、细描边、硬阴影的问题便签。

## 十、复刻时的优先级

1. 先复刻双主题、标题层级、留白和蓝色斜切转场；这是识别度主体。
2. 再实现卡片分批揭示、流程节点和证据高亮；这是信息节奏主体。
3. 最后实现 3D 轮播和轻微旋转；这些是局部亮点，不应泛化到全片。
4. 不引入秋芝风格的星空、紫色头像、黄绿霓虹标签和强辉光，以免跨风格串味。
