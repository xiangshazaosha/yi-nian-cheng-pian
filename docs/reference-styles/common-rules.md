# 跨风格公共规则与适用边界

> 本文是所有设计风格的共同入口与冲突处理说明，不是新的统一视觉皮肤。风格总索引：[README.md](./README.md)；可复用实现：[包装库](../packaging-library/README.md)。

## 1. 文档怎么分层

| 层级 | 位置 | 管什么 | 不管什么 |
| --- | --- | --- | --- |
| 项目边界与阶段规则 | `AGENTS.md`、`docs/workflows/README.md` 对应入口 | 跨阶段权限与确认；当前阶段的字幕、素材、审片、渲染及交付约束 | 不强制所有风格同色、同头像形状，不要求所有阶段细则常驻 |
| 公共制作规则 | 本文、`docs/02-content-planning.md`、`docs/03-remotion-production.md` | 信息职责、时间轴、媒体使用、真实性、空间与验证 | 不规定跨风格统一的背景、圆角、辉光或弹跳 |
| 风格规则 | `docs/reference-styles/<风格名>/README.md` 或既有风格归档文件 | 色板、字体、图形、构图、头像、动效语言、禁用外观 | 不改写字幕或免除工程与交付约束 |
| 包装实现 | `docs/packaging-library/` 与 `remotion-clone/src/` | 组件机制、API、具体配方和音效职责 | 组件历史默认皮肤不自动升级为全局规则 |
| 单片记录 | `remotion-clone/review/workflow-flash/<片名>/` | 素材、样张、用户选择、片级例外、验证状态 | 不把某条片的人数、数值、UI 坐标固化成所有片的规定 |

旧风格文件不为统一命名而搬家。双色类保留现有“风格归档.md”，具名新风格使用各自目录的 `README.md`。公共机制可以复用，风格外观必须显式选用。

## 2. 冲突怎么处理

1. 先遵守当前用户明确要求和项目硬约束；有真实冲突时说明并解决，不自行声称某风格可免除字幕、真实性或同步要求。
2. 同一视觉属性以选定风格文档为准，覆盖历史组件默认外观。例如目标风格规定无辉光，就不能沿用 `CircularAvatar` 的默认紫色辉光。
3. 片级例外写入项目登记，注明用户依据、影响范围和验证方法；不静默改掉其他风格。
4. 风格文档没有规定的属性，先按本风格语言补齐，不能自动从其他风格复制。新增通用组件仍须走[扩展判定](../packaging-library/extension-rules.md)。
5. **确认状态分开记**：选定视觉风格不等于字幕已校正、动效已验收或整片已完成。已确认的风格不反复索取同一选择确认；具体未完成的制作步骤仍须完成。

## 3. 全部风格必须遵守的公共规则

以下是适用范围说明；具体技术细节以链接文档为权威源，不在这里维护另一套数值版本。

| 公共规则 | 适用边界 / 权威位置 |
| --- | --- |
| 字幕先校正、保留原件、记录差异 | 正式时间轴制作先使用校正版；疑难词核音频，未决项不进入最终成片。见[字幕规则](../workflows/subtitles.md)。单纯风格样张必须标明不是成片，不伪造 subtitle。 |
| 字幕与设计文字分层 | `subtitle` 忠实时间轴；`title / keyword / summary / label` 只概括当时已成立的语义。不能提前泄露后句，不能拿整句字幕冒充标题。 |
| 字幕默认裸排 | 不加卡片、边框、阴影底板或卡片内边距。可按背景调整字色与克制字形描边/投影；只有用户明确要求才记录片级底板例外。 |
| 真实证据不可被风格改写 | 真人、UI、文件名、数值、单位、模型版本保真。不能用生成脸替代源口播；不能把重绘界面冒充真实截图。历史材料不标“最新”。 |
| B-roll 自带烧入字幕避免双字幕 | 先检测并登记，在相应区间隐藏重叠的 Remotion 字幕。 |
| 重点与安全区优先 | 字幕、人物脸部、图表和操作目标不得互相遮挡；不删核心信息来解决穿线或越界。安全区需要逐镜计算，不固定套坐标。 |
| ROI 以原分辨率完整边界为准 | 缩放和平移共享进度；入口、中段、到达、保持、退出均检查。只证明静态终点安全，不能宣称整段运镜通过。 |
| 连线只有一个几何真源 | 线、移动对象、箭头共享路径与进度；端点停在对象边缘，不能穿字或在终点提前悬空。 |
| 媒体和音画同步 | 素材通过 `staticFile()`；视频显式静音，主音轨独立管理；源偏移固定。见[Remotion 使用约束](../03-remotion-production.md)。 |
| 音效职责和口播优先 | 动作分类、同动作同规则、相对口播响度校准、自带音效排除窗均继承[音效规则](../packaging-library/sfx-rules.md)。音色可随风格变化，历史默认增益不代表已经校准。 |
| 逐段验证与正式交付 | 先小范围排错，再整片；长片分段与流验证见[制作规范](../03-remotion-production.md)，输出目录与覆盖验收见[审片目录规则](../../remotion-clone/review/workflow-flash/README.md)。发布资料须用户另行明确请求。 |

## 4. 不是公共硬规则的属性

下列属性由目标风格或当前镜头决定，不能因某个历史组件写了“默认 / 必用”就跨风格套用：

- 纯黑、暖白、绿色、蓝色等背景选择；黄色是否是唯一强调色。
- 圆头像或方头像、头像面积倍率、固定左下位置、是否每张数据页都放头像。当前用户已明确要求的头像配置必须保留；未规定时由风格构图决定。
- 紫色边框、渐变、辉光、星空、径向暗角、玻璃质感、重阴影。
- 卡片外形、默认圆角与描边粗细、固定面板面积。
- 文字字号、弹性系数、位移幅度、持续漂浮、黑场转场与转场时长。
- 历史项目某一首 BGM、某个音效文件、固定增益、固定音效时间窗。

**特别说明**：包装库的 `CaptionBar` 历史“半透明字幕底板”不能覆盖裸排硬规则；`TextureBackground` 的“全局底层”与 `CircularAvatar` 的“所有 B-roll 必用”描述属于其原始风格配方，不是所有风格的共同要求。

## 5. 新风格归档最低内容

每个风格规则文档应写明：触发名称、确认范围、视觉基准、色板与字形、语义任务 × 使用环境、构图与头像、安全区、字幕、动效状态、公共规则继承/覆盖表、禁用项、实现入口及验收清单。

新增或变更风格后同步[风格索引](./README.md)与目标风格文档；[包装库入口](../packaging-library/README.md)只链接风格索引，不重复维护风格配方、别名或单片状态。仅新增风格规则不增加通用组件数量；确有通用方案或适用范围变更时才同步包装条目，新增组件/API 按扩展流程登记并验证当前代码、实际调用与方案文档。
