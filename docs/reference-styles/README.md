# 设计风格与参考视频分类索引

> 先分类，再扒片。分类解决“这套规则属于哪种片”，四类模块拆解解决“这套片具体怎么做”。

## 文档入口与规则分层

- **跨风格公共规则**：[common-rules.md](./common-rules.md)，说明哪些工程、字幕、证据与验收规则始终适用，哪些历史默认外观不能跨风格套用。
- **各风格规则**：放在本目录的具名风格子目录中。旧文档保留原名，新风格以 `<风格名>/README.md` 为主规则表。
- **包装组件与机制**：[包装库索引](../packaging-library/README.md)。其秋芝风历史皮肤不是全部风格的统一外观。
- **单片选择与审片**：放在 `remotion-clone/review/workflow-flash/<片名>/`，不混入公共规则。

## 分类原则

按画面中承担主要叙事和信息表达的载体判定一个**主风格**。截图、图标、字幕、短暂转场只能作为次要特征，不能因为同屏出现就把多个风格混成一个默认池。

| 主风格 | 主要判据 | 不因这些元素改变分类 |
| --- | --- | --- |
| 纯文案类 | 标题、短句、卡片、数字、流程图或排版动画承担主要叙事；无需人物和连续实拍也能完整表达 | 少量截图、图标、产品界面证据 |
| 双色类 | 近黑画布与克制黄构成双锚点，真人圆形头像与语义图形交替承载信息；暖白与灰只建立层级 | 少量软件身份色、已有成片插入、真实证据截图 |
| 秋芝风 | 真人口播、圆形头像和 UI 演示交替承担叙事；暗色星空、紫色描边和黄绿橙标签形成稳定识别 | 手机 / 网页 / 文档样机、少量 3D 吉祥物 |
| 真人口播类 | 人物表情、口播和镜头表现是主要载体，包装文字用于辅助强调 | 字幕、角标、少量 B-roll |
| 屏幕演示类 | 连续录屏、软件操作路径或产品 UI 是主要载体 | 小头像、步骤标签、鼠标高亮 |
| 素材混剪类 | 多段实拍、图库、采访或环境镜头的剪接关系承担主要叙事 | 旁白字幕、章节标题 |
| 混合叙事类 | 至少两种载体在较长段落内交替承担主叙事，去掉任一类都会破坏主体结构 | 仅偶尔插入另一类素材不算混合 |

边界判断：先问“静音后只看画面，主要信息还能靠什么读懂”；再问“删掉人物 / 录屏 / 实拍 / 文字中的哪一类，主体是否仍成立”。仍有争议时，选择时间占比和信息承载量同时更高的一类，并把另一类写成次要特征。

## 归档与复用规则

1. 每条视频只放入一个主风格目录，文档开头写主风格、次要特征、判定依据和排除项。
2. 主体拆解使用“语义任务 × 使用环境”矩阵，说明何时使用、为什么使用和如何递进；不得用原片时间轴流水账代替规则抽象。
3. 风格目录内沉淀本风格的构图、色板、排版密度、节奏和转场配方；不得无标记复制到其他风格。
4. 真正跨风格成立的机制可标为“共享基础”，例如固定源偏移、时间轴同步或通用淡入。
5. 要把扒片结果加入 `docs/packaging-library/` 时，仍须走 `extension-rules.md`；方案文档需写明“适用风格”。
6. 成片规划先选主风格，默认只读取该风格目录和共享基础。混合叙事类也必须逐段标出载体，不得把所有组件同时堆入一段。

### 动效共用原则

动效底层机制可以跨风格共用，动效预设不能无差别混用。`spring`、淡入、位移、线条绘制、光标路径等代码属于共享机制；时长、位移幅度、overshoot、缓动、颜色、辉光、音效和组合频率属于风格预设。复用机制时必须从目标风格读取参数，详见各风格目录。
