# 风格归档：双色类

> 来源案例：`AI干进专业工作` 阶段 1  
> 主要实现：`remotion-clone/src/ai-professional-work/Stage1Full.tsx`  
> 风格触发词：**双色类 / 双色风格 / 双色风**  
> 次要特征：真人圆形头像、暖白包装画布、B-roll 原生黑底、语义图形、克制科技感、少量软件身份色。

## 一、风格定义

### 一句话风格

以暖白画布和低饱和黄色为两枚视觉锚点，用近黑与灰色建立文字层级；真人圆形头像负责保留口播连接，卡片、节点、动态连线和证据画面负责解释专业信息。只有 B-roll 源画面本身需要黑底时，才保留纯黑视频区。

### “双色”的准确含义

- 双色不是强制全片只有两个 RGB 值，而是只保留两枚有识别度的视觉锚点：**暖白空间 + 克制黄强调**。
- 无 B-roll 的 Remotion 包装页默认使用暖白，不再为了统一而铺满纯黑；纯黑主要服从 B-roll 原生构图和必要的短过渡。
- 暖白和灰色属于中性色层级，不作为额外品牌色扩张。
- Word 蓝、Excel 绿、PowerPoint 橙、产品官方图标色等只有在颜色承担对象身份时才允许小面积出现。
- 身份色只进入图标、数据节点或必要状态，不能扩散到背景、标题、头像框、卡片外发光和装饰线。

### 与纯文案类的区别

- **纯文案类**：黑 / 暖白报告页、皇家蓝结构色、企业研究报告式排版；参考片默认不使用主播头像。
- **双色类**：暖白包装页贯穿、B-roll 原生黑底按需保留、黄色作为唯一常规强调色，允许并通常保留黄色细边圆形头像；语义图形和真人口播共同完成叙事。
- 用户点名双色风时，不能套入纯文案类的皇家蓝转场、暖白报告页、无头像边界；用户点名纯文案风时，也不能默认套入双色类的黄色头像体系。

## 二、色彩与材质

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| 主背景 | `#EEEAE1` | 无 B-roll 的暖白包装画布 |
| 主文字 | `#171813` | 暖白页上的标题、结论和核心标签 |
| 次文字 | `#6F7069` | 暖白页上的英文眉题、说明和非激活信息 |
| 强调黄 | `#D8C94B` | 关键词、路径、头像细边、激活态和状态节点 |
| 暖灰卡片 | `#E5E0D6` | Skill、信息卡和局部容器 |
| B-roll 黑底 | `#050505` | 只承接源 B-roll 的原生黑色构图；不叠随机白点 |

### 代码实现入口

- 双色风代码必须从 `remotion-clone/src/styles/duotone.ts` 读取颜色、卡片和头像令牌，禁止在单条成片中重新手写近似色、第三强调色、粗头像外圈或卡片重阴影。
- `remotion-clone/src/lib/theme.ts`、`HighlightTag` 和 `CircularAvatar` 的默认外观来自秋芝风历史实现；双色风可以复用几何与时间轴机制，但不能直接继承其黄绿橙色块、紫色头像和辉光预设。
- B-roll 源画面已有的青色、软件品牌色或状态色可原样保留；Remotion 新增的眉题、标题、卡片、头像框和装饰线仍只使用暖白、近黑、灰和克制黄。
- `npm run stylecheck:duotone --prefix remotion-clone` 会阻止方寸视觉代码重新引入秋芝色值、青色第三锚点或带紫色外观的历史组件；双色风成片在类型检查前先运行该检查。

材质以纯色、细描边和轻微层叠为主。禁止持续白色光点、彩色渐变背景、霓虹多色辉光和大面积黄色底板。

### 黄色使用边界

- 黄色是状态与路径信号，不是所有容器的默认边框。优先用于当前节点、小圆点、数字编号、短横线、路径端点和一次性关键词。
- 单帧原则上只保留 1–2 个明确黄色焦点；B-roll 源画面已有黄色时，Remotion 包装层继续减量，避免与源画面争夺强调权。
- “卡片边缘一条黄色识别边”仅适用于 Skill、文件、真实证据等具有独立对象身份的卡片，不得推广为观点卡、总结句、小游戏标签和全部流程节点的统一皮肤。

## 三、主构图模式

### 1. 真人全屏重音页

- 仅用于开头钩子、重要态度或段落重音，数量要少。
- 人物全屏时不加黑色信息框、圆角面板或人物外框。
- 通过字号、留白、短分隔线和单一黄色关键词组织信息。
- 优先利用原片自然留白直接排字。原片已有干净墙面或空白区时，禁止再铺满半屏暖白图层；确需增强对比度时只做文字局部的低透明柔化，不能在边缘达到完全不透明，也不能覆盖人物肩膀、环境纹理和空间光影。

### 2. 圆形头像 + 暖白包装页

- 默认头像位于左下安全区，黄色边框约 3px，无辉光；头像框不能比字幕、标题和当前核心信息更醒目。
- 头像外不增加方形底板或第二层彩色边框。
- `236px` 只作为画面宽松时的参考值；录屏文字密集、左下存在操作区或底部还需放字幕时，头像缩至 `204–216px`，并优先落在录屏框外留白区，只轻微压住框边，不遮挡正文和控制区。
- 标题通常位于左上或中左，语义图形位于右侧或中下，字幕留在底部中央安全区。
- B-roll 本身为黑底时保留黑色视频区和工具目录；可只做垂直避让，不能缩放破坏既有蒙版与排版。
- 人物由全屏进入头像时，优先调用共享的 `ArollToCircularAvatarTransition` 做连续位移、缩放和圆形裁切；本风格只覆盖为黄色 3px 细边、无辉光。

### 3. 左标题 + 右关系图

- 左侧使用英文眉题、两行中文大标题和一行黄色判断。
- 右侧使用节点、目标环、流程、拆分矩阵或卡片证据。
- 左右之间保留明显呼吸区；动态连线只能进入专用通道，不穿文字和卡片内容。

### 4. Skill / 文件证据卡

- 使用 MD、Word、Excel 等对象身份符号，文件名和真实内容层级必须来自实际资源。
- 卡片允许轻微透视、错层背板、斜切角或 1° 内的归正动画，使其具有轻微立体感，但不能做强烈 3D 翻转。
- 只有此类具有独立对象身份的证据卡，边缘才允许一条黄色识别边；其余描边保持低对比灰。该规则不得套用到普通观点、摘要、关键词和步骤文字。

### 5. 编辑式信息表达（默认）

- 默认不先画卡片。根据语义选择 `MarginNote` 边注、`ProcessRail` 流程轨、`LocatorLabel` 定位标签、`PullQuote` 观点重音或直接排版；只有内容本身是独立对象、证据或需要持续承载多层信息时才使用卡片。
- 简短观点和总结句优先使用裸排文字、短黄线、编号或局部括号，不套圆角底板。
- B-roll 已有成熟界面时，包装层以页边注释和目标定位为主，不再在底部堆一排“第二套 UI”。
- 不把所有元素固定在同一个 `right / bottom` 槽位。每帧先识别原画视觉重心、负空间、头像区和字幕区，再决定信息落点。

### 6. 已有成片插入

- 若主片和待插入片都已输出，直接硬剪掉目标区间，拼接“前段 + 插入片 + 后段”。
- 插入片只取画面，继续使用主片原音轨；不要回 Remotion 保留旧画面再叠一层视频。

## 四、排版纪律

- 英文眉题：约 15–18px，高字间距、灰色。
- 中文主标题：约 56–68px，粗黑、1–2 行、左对齐。
- 结论句 / PullQuote：约 26–30px，中粗字重，可配一条短黄线。
- 流程名称 / 定位标签：约 22–26px；编号、状态和元信息使用 15–18px 灰色或小面积黄色。
- 证据卡主标题：约 24–30px；文件名和说明使用 14–18px 灰色。卡片禁止只放一条与字幕同构的完整口语句。
- 字幕约 40–42px，一行优先；字幕、标题、当前核心图形的优先级始终高于头像边框和装饰线。卡片正文必须通过更小字号、不同字重和“编号 / 标题 / 元信息”层级与字幕明显区分。
- **字幕不是卡片**：逐字口播字幕默认裸排，不加底板、圆角、边框、内边距或卡片阴影；浅色画面用近黑字，深色画面用暖白字，复杂 B-roll 只用克制的字形描边/投影和安全区位置保证可读。证据卡、状态卡等确有独立对象身份时才按同系令牌使用卡片，不能把这项许可套到字幕层。只有用户明确要求字幕底板等特殊无障碍呈现时才作为片级例外另记并逐帧验收。
- 同屏只保留一个主要判断、一个证据区和一条主要运动路径。

## 五、动效语法

### 文字与卡片

- 文字以 8–16 帧的水平位移、遮罩揭示或一次性轻微斜切回正进入。
- 常用位移 18–42px，斜切不超过 `1.1°`。
- 卡片可带轻微透视、横向进入和归正；禁止上下反复震动、高频弹跳和连续缩放。

### 粒子与漂移

- 粒子只表达传递、拆分、汇聚或到达，每次 3–6 个，0.6–1.4 秒结束。
- 持续漂移周期不短于 4 秒，振幅通常不超过 1–2px。
- 禁止用随机白点填满纯黑画布。

### 动态连线

- 一条关系线只有一个几何真源。SVG 路径、移动点和箭头必须共享同一组控制点和同一个进度值。
- 黄色点始终贴在线条绘制端点；箭头绑定当前线头移动，或在线条到达后再出现。
- 节点先出现，连线随后生长，结论文字最后进入。
- 连线端点停在卡片、胶囊或文字安全区边界；不能靠删除文字解决穿线，也不能把动态指向线降级为静态分隔线。

### 黑底与暖白切换

- B-roll 完成一次明确操作、点击或结果反馈后，可以在语义完成点直接切入完整暖白画布。
- 禁止用半透明或局部上推的暖白层长期压住 B-roll；这会形成灰带、残留 UI 和“毛切一半”的观感。
- 切换帧同步完成背景、目录和字幕字色反转：黑底使用暖白字，暖白页使用近黑字。

## 六、头像与黑帧处理

- B-roll 或 A-roll 出现黑帧时，不使用无关头像视频补口型，也不把人物突然切成全屏。
- 在有效头像画面结束前，让圆形头像向下沉降并淡出；黑帧区由与口播语义一致的 Remotion 图形接管。
- 源画面恢复时，头像反向升起并淡入。
- 中间包装内容必须与前后头像动势贯通，不能像独立贴片突然出现。

## 七、典型组合配方

### 配方 A：专业落差

- 左侧标题说明“教程为何到岗位失效”。
- 右侧使用教程轨与岗位轨、节点激活和断开符号表达落差。
- 黄色只标当前断点或关键岗位。

### 配方 B：AI 射程

- 左侧大标题“把 AI 拉进你的射程”。
- 右侧 AI 胶囊通过一条黄色路径连接到专业目标环。
- 路径从胶囊边界开始，到目标边界结束，不能穿过标签文字。

### 配方 C：Skill 接管黑帧

- 头像下沉时，MD 引用点沿同一条贝塞尔路径进入真实 Skill 卡。
- 卡片稳定后，动态箭头从卡片边界指向“方法论已经整理成 Skill”。
- 路径、点、箭头逐帧一致；头像恢复时整套内容反向退出。

### 配方 D：整体不可自动化，拆成局部

- 左侧用“整项工作”与否定符号建立限制。
- 右侧将输入、计算、判断、执行、校验、输出拆成局部矩阵。
- 通过黄色当前节点说明“不是全自动，而是可控局部自动化”。

## 八、禁止项

- 紫色头像框、黄绿霓虹并用、多色渐变和随机彩色粒子。
- 人物全屏外再套黑框、卡片或粗边容器。
- 纯黑画布上的持续白色星点和非语义光斑。
- 高频上下抖动、连续弹跳、反复放大缩小。
- 为解决穿线而删除核心文字。
- 路径、移动点和箭头分别使用不同运动公式。
- 已有成片片段仍回 Remotion 叠在旧片之上。

## 九、验收清单

1. 常规强调色是否只有黄色，原生身份色是否只停留在必要对象内部。
2. 头像边框是否服从标题、字幕和核心图形的视觉层级。
3. 无 B-roll 包装页是否使用暖白；B-roll 黑底是否干净，没有随机白点和不必要辉光。
4. 文字、卡片和图形是否按语义顺序进入，而不是同时躁动。
5. 动态线、点、箭头是否在入口、中段、到达和退出帧保持一致。
6. 是否存在穿字、压字幕、越界、卡片拥挤或装饰线抢信息的问题。
7. 黑帧是否由相关图形接管，头像沉降与恢复是否连贯。
8. 已有成片替换是否使用硬剪拼接并保留主片音轨。
