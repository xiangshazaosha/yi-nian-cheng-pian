# 01 参考视频拆解

> 阶段一文档。完整观看参考视频，拆成 Remotion 可复用的具体规则。
> 不要把每个画面归纳成互斥的"模式 A、模式 B"。一个实际画面 = 主构图 + 内容组件 + 视觉处理 + 动效模块。

## 零、先做风格分类

拆构图和组件之前，先按 [`reference-styles/README.md`](./reference-styles/README.md) 判定一个**主风格**，必要时补充次要特征。主风格按“谁承担主要信息表达”判断，不按是否偶尔出现截图、图标或字幕判断。

- 每条参考视频只进入一个主风格目录：`docs/reference-styles/<主风格>/<片名>-拆解.md`；
- 不把不同主风格的构图、色板和节奏一股脑合并；
- 跨风格都成立的基础机制可单独标为“共享”，风格专属配方必须保留所属风格；
- 当前成片选型默认只读取目标主风格和共享基础，不自动混用其他风格。

## 视频源

参考视频固定位于 `参考视频/` 目录下。无需询问用户路径。
使用当前可用的视频探测、抽帧和图像查看能力完成全片观看与关键帧分析；不要依赖特定代理名。

## 核心拆解单位：语义任务 × 使用环境

参考片多长、某个画面出现在第几秒，不是可复用规则。抽帧时码只用于分析者定位原片、确认没有漏看；主文档不得默认输出“时间段 + 画面概述”的逐段流水账。

先把全片重复出现的画面归并成若干**语义场景**。每种语义场景必须说明：

1. **语义任务**：钩子、提出问题、建立可信度、解释方法、展示证据、风险警告、对比证明、结论收束、CTA 等；
2. **触发语义**：口播或文案出现什么信息时应该调用；
3. **使用环境**：适合什么题材、叙事阶段、信息密度、情绪和观看任务；
4. **画面职责**：观众第一眼看什么、随后理解什么；
5. **构图与组件组合**：用哪些构图、卡片、图表、证据和视觉处理；
6. **递进逻辑**：元素为什么按这个顺序出现，而不是只记录它何时出现；
7. **禁用环境**：哪些内容不适合套用该场景。

同一种语义场景即使在原片出现多次也只总结一次。只有用户明确要求逐镜复刻、剪辑点、字幕同步或时间轴诊断时，才把原片时码作为附录输出。

## 一、主构图模式库

主构图模式决定人物与主要信息区域的空间关系。例如：

- 构图 A：人物左侧 + 右侧信息区；
- 构图 B：人物右侧 + 左侧信息区；
- 构图 C：人物居中 + 两侧辅助信息；
- 构图 D：人物缩小 + 大面积图表；
- 构图 E：人物退场 + 全屏信息画面；
- 构图 F：左右分屏；
- 构图 G：全屏章节标题或过渡画面。

每种主构图模式说明：

1. 人物的位置、大小和裁切范围；
2. 标题、字幕和信息区的位置；
3. 适合承载的内容；
4. 信息容量上限；
5. 不适合使用的场景；
6. 是否需要人物移动或缩放。

每个信息段原则上只选一个主构图；段内发生明显画面切换时可切换。

## 二、内容组件库

可叠加在主构图中的组件，例如：大标题、副标题、一句话摘要、事实卡、观点卡、步骤卡、数字卡、对比卡、图表、流程图、时间轴、截图或产品界面、图标组合、关键词强调、口播字幕。

每个组件说明：

1. 位置和尺寸；
2. 字体与颜色层级；
3. 单次适合展示多少信息；
4. 与哪些组件可以同时出现；
5. 与哪些组件不宜同时出现；
6. 进入、强调和退出方式。

同一信息段可组合多个组件，但不得无条件把标题、副标题、摘要、三张卡片、图表和字幕同时堆在画面上。

## 三、视觉处理模块库

可复用的视觉处理，包括：人物抠像、几何蒙版、圆角裁切、渐变羽化、描边、阴影、辉光、背景虚化、局部放大、暗角、聚光区域、前景遮挡、背景纹理、半透明色块。

同一画面可叠加多个模块，但要说明各模块的图层顺序和作用。

## 四、动效与转场模块库

参考视频中重复使用的动画模块，例如：标题滑入、摘要淡入、卡片逐张出现、数字滚动、图表生长、线条绘制、遮罩揭示、关键词放大、人物缩小让位、人物横移、卡片收拢、模糊转清晰、蒙版擦除转场、全屏色块转场。

每个动效模块说明：

1. 作用对象；
2. 开始时机；
3. 持续时间；
4. 动画方向；
5. 缓动类型；
6. 是否与语音重音或停顿同步；
7. 可以与哪些动效组合；
8. 是否适合高频重复使用。

动效必须拆成两层：

- **共享机制**：`spring`、淡入、位移、缩放、线条绘制、遮罩揭示、光标路径等，可跨风格复用代码；
- **风格预设**：时长、动幅、overshoot、方向、缓动、颜色、辉光、音效和组合频率，归入具体风格。

因此“同一个动画函数可共用”不代表“原参数可直接跨风格使用”。复用时必须从目标风格读取预设。

## 组合方式

分析每个去重后的语义场景时，输出完整组合（不只是"参考模式 A"）：

- 语义任务、触发语义和使用环境；
- 主构图模式；
- 使用的内容组件；
- 使用的蒙版或视觉处理；
- 使用的动效模块；
- 元素出现顺序；
- 哪些元素常驻，哪些分批出现；
- 是否在段落内部切换构图。

主构图模式通常只能有一个，但内容组件、视觉处理和动效模块可按需组合。

## 阶段一输出

1. 风格身份证：主风格、次要特征、判定依据、风格边界；
2. 语义任务 × 使用环境矩阵；
3. 主构图模式库；
4. 内容组件库；
5. 视觉处理模块库；
6. 动效与转场模块库；
7. 常用组合方式示例；
8. Remotion 实现可行性说明（每个视觉效果标注：能否直接实现、建议用 React/SVG/CSS/Canvas/Lottie、实现难度、是否值得做成可复用组件、适用风格）。
