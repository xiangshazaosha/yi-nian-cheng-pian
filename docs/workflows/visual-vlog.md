# 视觉 Vlog 剪辑工作流

本项目原创方法初版。适用于明确要求剪辑的风景、旅行、城市漫步、自然观察等以画面和现场体验为主体的内容；少量人声可以保留，但不承担默认叙事骨架。不是外部技能安装说明，也不表示自动执行能力已齐备。

## 入口与按需阅读

- 动作与工具选择仍由[素材入口](./intake.md)决定；这里只决定选什么、怎样排列和如何验收。仅调色、仅分析或已剪好只包装时，不启动重剪。
- 先读本入口和当前阶段，不顺读所有章节。找素材读“选段”；编排读“表达与结构”“镜头与节奏”；精剪读“声音与色彩”；审片读“验证与交接”。研究依据只在需要解释取舍或维护本方法时读[候选比较（未随公开版分发）](../public-release-scope.md)。
- 不预加载口播粗剪、ASR、字幕、包装风格或外部技能。没有待转写的人声就不调用 Whisper/ChatCut；自然环境声不按静音或口播停顿规则删除。
- 当前方法可指导分析与规划。实际写入时间线前按“执行边界”检查，不把文档交付说成已完成剪辑。

## 表达与结构

先从已有要求提取片长范围、画幅、希望留下的感受、必用/禁用素材、音乐与原声偏好。只追问会改变结果的缺项；尚未确定的事项标为建议，不把默认建议当成用户已确认。

给当前片写一句表达目标，例如“从街头的匆忙走到海边的松弛”。这不是旁白台词；后续每段应能说明与此目标的关系。若素材只能表达一种氛围，就做观察段落，不虚构旅行路线、日出日落顺序或戏剧冲突。

| 素材能够支持的关系 | 可选组织方式 | 应避免 |
| --- | --- | --- |
| 有明确的到达、经过和离开 | 以空间体验推进，选必要节点，让观众理解变化 | 按文件名机械排序；假装不同时地是连续行程 |
| 同一地方的光、风、人物或天气发生变化 | 以观察和变化推进，让细节与开阔画面互相解释 | 硬造三幕冲突；为了快而删掉变化酝酿 |
| 缺少连续事件，但存在形状、动作或情绪呼应 | 主题联想式编排，允许有意识的时间省略 | 将意象联想包装成真实因果；只靠花哨转场连接无关画面 |

这些是可选择的方法，不是每片必须填满的模板。画面本身是主内容，不统一称作口播 B-roll。包装文字和配音不能替代缺失的画面逻辑。

## 选段：先找观看价值，再找可用边界

长素材浏览、带时间的观察、动态复核、源入出点与共用证据记录统一按[长素材视觉选段](./visual-selection.md)执行，只读当前步骤。口播与 Vlog 可以复用同一批源选段事实，但不能直接复用“该用哪段”的结论；这里不加载 SRT 配画面分支。

当前片 `vlog-plan.md` 只引用共用 `visual-selects.md` 的候选编号，记录本片的观看任务、段落顺序、采用区间、声音安排与选择理由，不维护第二份源观察或新增可执行 JSON 协议。若已有旧选段记录，保留历史并明确当前权威位置，不静默删除。

将内容重复的镜头放在一起比较：哪个更有层次、变化、方向感或现场声音？保留承担不同任务的镜头，不要求每个来源平均出镜。任务可以是建立环境、揭示、动作推进、细节、对比、停留或收束，不强制每段齐全。

技术干净不是唯一选择标准，但缺陷会妨碍观看时不能只因“情绪好”忽略。素材没有所需画面时，优先缩短或重组段落，再提出具体补拍需求；不默认生成或搜外部素材伪装现场。

## 镜头与节奏：以段落成立为单位

### 先组织视觉段落

每段先说明：观众现在看什么、有什么新变化、为什么转到下一段。镜头可以建立位置、带出动作、靠近细节、揭示空间或留下余韵；不固定执行“远中近”循环。

- 开头选能建立兴趣或氛围的画面，不强制精彩镜头预告，避免开头耗尽唯一重要揭示。
- 相邻镜头至少有一个成立的关系：同一空间的补充、动作延续、视线/构图引导、主题呼应、声音引入，或有意的反差。没有关系先换镜头或重排，而不是加转场遮掩。
- 方向相反或空间突变时，先判断是否造成误解；可用环境全景、动作结束或过渡细节重新建立方位。不能为强行顺方向而默认镜像含文字、地标或人物的画面。
- 同景别、同运动、同信息的连续美景容易重复。选择带来新观察的镜头；回到同一意象时说明它与前一次相比有什么变化。
- 收尾选择真正完成本片感受的动作或画面，不固定套夕阳、背影、关机或“晚安”。

### 再确定每个切点

依次问：观众看清主体了吗？动作或揭示是否到达有意义的位置？继续保留是否仍有变化或感受？下一镜能否接住注意力？据此确定候选点，再回看前后动态区间微调。

- 不统一 3 秒、4 秒一刀，不用语音空白、运动峰值或节拍检测直接决定删留。
- 静景可以长留，运动镜头也不必快切；“长短变化”服务观看，而不是凑比例。
- 可以切在动作中以延续运动，也可以留到动作落定；两者取决于想表达的体验，不规定所有动作必须完整播放。
- 音乐主导的蒙太奇可先试音乐段落，再调画面；观察型段落可先整理画面与原声。不强制所有片先配乐或最后才配乐。
- 节拍是候选参照，不是每拍必切。高潮与安静段需要对比；慢节奏仍须有观看内容，快节奏仍须看得懂。
- 默认先用直接切换判断结构。叠化、变速、防抖等只为具体问题使用，核对余量、裁切及伪影；不把“电影感”等同于慢放、黑边或转场数量。

## 声音与色彩

### 声音也承担现场体验

- 先辨认值得保留的风、浪、脚步、车声和现场互动。纯视觉不等于无声，去掉口播也不等于全片静音后铺音乐。
- 每段判断谁是声音主体：现场声、音乐或有意义的人声；其余让位，不固定套全片音量值。没有 BGM 的段落同样成立。
- 根据空间和情绪需要，让下一场声音先到，或让上一场余声延续；不能用无关现场声制造错误地点或事件印象。外来音效与音乐须登记来源和使用权限。
- 小范围试听接缝，避免爆音、突断、底噪抽吸和配乐突兀截断；最终全片回听检查整体强弱、左右声道和细节。不会因检测通过就声称混音听感通过。
- 新生成音乐、配音、购买素材或联网上传不是默认步骤。需要时按现有对应入口与用户授权处理。

### 色彩服务同一段体验

- 先核对素材色彩标记与实际曝光，不凭“画面灰”就断言 Log；未知输入条件先查证，不盲套还原 LUT。
- 将基础曝光、白平衡与相邻镜头匹配，与风格化分开处理；保留天气和时段的合理差异，不把阴天与夕阳强拉成一样。
- 用当前段代表画面比较明暗、肤色（如有）、天空与植被，再看运动中的变化。保留可撤回调整，不直接改写原片。
- 自动调色能力必须另行验证；软件已安装或时间线已成功写入不代表调色已通过。选择工具与确认边界见[素材入口](./intake.md#剪辑与调色工具选择)。

## 执行边界

- 创意规划和软件执行分开：确认采用的结构、必用片段与风格后，再核对所选工具能否完成多素材重排、声画分离、混合帧率、变速和调色等本片实际需要的操作。只检查需要的能力，不强装全套依赖。
- 现有[最小剪辑协议](./editing-contract.md)是单口播源删除与 B-roll 覆盖，**不能直接表达本流程的多素材视觉编排**。`vlog-plan.md` 是创意记录；实际按已审阅选段的顺序生成剪映草稿时才读[独立 Vlog 执行](./visual-selection-execution.md#6-纯视觉-vlog-独立编排与草稿)，它使用内部审阅清单，不扩展旧口播协议、不需要 SRT。
- 执行适配未通过时，可以交付有证据的选段与编排建议，但明确标记“待执行”；不把说明文档、预览图或拼接建议当作真实可编辑工程。
- 实际执行使用新版本时间线，保留已批准版本；源入出点、源与目标时间基准、变速和声画偏移都要能复核。混合帧率、VFR 和代理映射不得静默猜测。
- 如需新增执行适配，另按工程验证入口实施我们自己的代码；本方法不授权下载或移植参考项目的代码/原方案，不授权 UI 操作或购买。

## 验证与交接

1. **结构审阅**：展示简短段落安排、关键选段与未决项，不堆全库缩略图。核对必用/禁用内容、事实关系与表达目标。
2. **小段验证**：选择能代表本片难点的连续段，包含真正的镜头连接与声音变化，不只展示最好看的一帧。先检查并展示代表静帧，保留根规则的用户确认闸门；短段样片用于进一步确认动态节奏与声画关系，不能由静帧代替。已确认的同一选择不重复询问。
3. **扩展制作**：小段确认后再扩展；全片渲染仍遵守根规则和[审片目录规则](../../remotion-clone/review/workflow-flash/README.md)。重要风格或结构改变要展示受影响部分，不重走无关步骤。
4. **双重检查**：结构检查核对源范围、实际写入、遗漏/意外重复、非预期黑帧与空隙；有意留白或轨道重叠不是一律错误。正常速度看听检查跳动、注意力丢失、节奏重复、音频接缝、裁切与色差；抽样检查不能冒充全片验收。
5. **按实际范围交接**：交付已实现的可编辑时间线、必要来源登记与审片记录；只有确实导出并验收才称成片。字幕仅在有需呈现的人声时走[字幕规则](./subtitles.md)；无口播不制造 SRT 前置。字幕未决项不绕过原有闸门。

进入独立文字/图形包装时才读取[内容规划](../02-content-planning.md)及选定风格；本方法不复制包装参数，也不默认把风景片变成口播信息卡。发布资料、封面与发送继续按用户明确请求进入。

当前状态：方法、命名路由、共用概览/加密抽帧、证据合并及受限的多素材 Vlog 剪映审片草稿生成已实现；视觉判断仍由助手实际观察。合成媒体文件回读不等于真实片端到端验收；自动配乐、调色等不是本版能力。首条实片验证后，只根据实际问题改进，不将一次样片偏好固化为所有 Vlog 的硬规则。
