# 口播粗剪默认规则

仅在按[素材入口](./intake.md)判定进入口播粗剪／语音剪辑时读取，包含当前片无提示词首次给素材路径的默认入口。剪映草稿人工编辑后的导出视频回流、明确已剪好或只要求包装时不重剪；本规则不扩大当前对象与限定范围。粗剪、精剪和定剪的命名见素材入口。

本页连同执行与交付检查一起读取；依据字幕作判断时还须遵守[字幕规则](./subtitles.md)的源时间轴、校正和疑难词核查要求。已有有效时间轴不自动重转写；只有实际生成/登记草稿时才读剪映操作包。

## 默认剪辑判断

1. **顺序**：用户明确文件名即顺序时，按数字自然顺序排列（1、2、…、10），不能按字典顺序或预检挑出的“主视频”漏掉其余素材。
2. **气口与停顿**：只处理**超过 0.2 秒**且可确认的气口／停顿，剪掉多余部分，默认保留约 **0.2 秒**；原本等于或短于 0.2 秒的不剪、不加长。这是压缩停顿，不是加速或变速。保护字头、字尾，按源帧核对；只删完整非语音帧，不强求无法表示的亚帧边界。不增加静音、不造黑场；声音重叠、边界拿不准或疑似漏识别时保留并标记，不把正常发音误当气口删掉。用户明确要求整段气口删除时才另选零保留模式。
3. **不流畅**：清理明确的卡词、无意义口头填充、失败起句和被后面完整说法覆盖的尝试；不因语速慢、技术术语或表达不够漂亮而删掉独有信息。不按“然后／所以／这个”等词表机械全删。用户已确认的常用语气词按[字幕口播习惯](./subtitles.md#用户已确认的口播习惯)保留，不被通用口癖列表覆盖。
4. **去重留末遍**：同一语义的多次重录，保留**最后一次完整表达的段落／尝试**，不是只保留最后一句。跨 ASR 行判断完整意义；最后一次明显残缺、与前文矛盾或仍需早先独有前提时，保留必要上下文并标待审，不无声改用别次，也不拼凑不同尝试的半句话。
5. **疑点保留**：个别不确定的内容先留在可编辑时间线，在内部记录源片、源区间与原因。对用户仅说明需要其判断的具体一句话和问题，不堆砌技术待审清单。取消片段染色、粉色标签及替代性时间线点标记，不往草稿写这些注释；疑点保留不能扩大成跳过整项停顿清理。
6. **原件与接管**：保留原素材和原始顺序备份时间线，导出引用完整媒体的可编辑草稿。默认粗剪请求已经包含草稿导出与交付，不要求用户再次说“导出”或“我要看候选”。粗剪不等于最终成片，不自动进入包装、发布或购买软件。

## 执行与验收

- **按本机已选路线执行**：本地走细粒度适配及本地草稿，Desktop 走其执行链；已有可用选择沿用，不为普通粗剪加载安装说明。缺完整源时间轴才转写，不因规则变化重剪已完成视频，也不在两边重复执行。
- Desktop 以真实词级数据、Script 和时间线为依据，`apply_script preview:true` 检查语义后再应用；气口显式 `only=silence, silence=compress:200`，不套默认250ms或机械删 fillers。具体见[剪映操作包](./jianying-editing.md)；本地按该包本地段执行，不要求 Desktop 工具。
- 来源／范围／连接异常先报告，不盲换通道。本机已选本地（含新机验收选定）使用[细粒度适配](./local-whisper-asr.md)；token 经连续 PCM 源偏移还原及文本／边界检查后驱动候选，不均分成假字词时间，不凭 SRT 空隙猜字音。
- 0.2 秒是默认**剪后保留目标**。30fps 下约 6 帧，30000/1001fps 下约 5.994 帧；按原始词级时间和源帧保护字音，允许必要的帧量化误差。刚超过阈值却没有完整可删非语音帧时可保持不变，不为追逐小数反复重剪。保留的是源素材中的静音，不插空白或把发音变速。明确本地分支的 `rough_cut.py` 默认 `threshold_us=200000, retain_us=200000`，明确零保留或旧阈值的历史任务须显式传原任务参数。静音伪 token `[... seconds silent]` 不能当作说出的词恢复进来；音轨能量不代替听审。
- 工具缓存不作为当前 schema 权威；分页读取到结束。导出后核验实际文件、每段源引用／源区间／目标位置、原声和媒体完整性，不补写编辑器标记。
- 未打开剪映、未听审或专业词未校正，就如实保留对应记录；这些状态不能互相替代，也不一律阻断可编辑粗剪草稿。是否能交付按下节区分，不把文件校验、语义检查或波形统计描述为已经完整听审。

### 能力检查与交付闸门

本节是粗剪草稿交付条件的唯一权威位置。**实际剪辑、技术核验、播放听审和最终成片验收是不同层级；不能把没有播放听审等同于没有做剪辑，也不能拿草稿文件存在冒充剪辑已做。**

#### 开始前核查能力

- 核对所选通道能否取得完整源词级时间、落实语义剪辑、处理停顿和输出可编辑草稿。Desktop 用 Script／原生导出，工具缺项先按[连接恢复](./chatcut-asr.md#启动与连接恢复)核查；本地用源时间／计划和生成器，缺环境接回部署，不因缺 Desktop 工具就误判本地不可用。
- 另行核对是否真有可供当前 Agent 使用的音频听取能力。没有就记为“未听审”，不得安排一个无法执行的“切点听审”必做阶段、假称已经听过，或让用户另配内部 Agent 才能交草稿。有音频导出、转写、波形或图片预览不等于当前 Agent 能听音频；未暴露工具也不能证明整个产品没有该能力。
- 句级 SRT 不等于词级边界。缺少可靠源词级时间时不凭字幕空隙硬切；确实无法完成停顿处理时，立即报告具体缺项，不自动换通道或等做到最后才告知。

#### 可编辑粗剪草稿交付

按下表区分输出前后检查：**核心剪辑与时间线技术核验通过，就输出草稿（Desktop 原生导出／本地既有生成器）；之后核验工程和媒体，通过即交付**。不把输出后的检查倒置成生成前提，不另加导出确认：

| 核心工作 | 至少核对的实际证据 | 不满足时 |
| --- | --- | --- |
| 语义去重与不流畅清理 | AI 已读完整原始表达；保留段与删除理由对应完整尝试，检查跨行／跨文件重录、独有信息和末次残缺 | 整项未做不能称粗剪草稿已完成；个别语义疑点保留原声，不机械删除 |
| 气口／停顿 | 真实源词级数据、工具实际处理结果、剪后源区间与保留量；无可删候选也须有实际检查依据 | 未执行不能写成“无须处理”；不能以标记或用户精剪代替整项工作 |
| 切点技术核验 | 全部源区间在范围内、时间线连续、切点与词级边界及源帧关系；检查相邻片段有无缺失／重复覆盖 | 异常先定位到当前语义窗，必要时恢复该处原声或缩小删除范围；不统一加余量冒充核验，也不把单个 ASR 边界交叉直接断言为听到截字 |
| 工程与媒体 | 导出前核对工程／活动时间线、原声原速、原始顺序备份和源媒体可用；导出后核对实际工程文件、全部区间引用与复制媒体哈希 | 错版、缺源、断轨、越界或导出失败必须修复，不能用“待听审”掩盖技术错误 |

- **只有未听审、未在剪映播放、或个别专业词待音频核对，不单独阻断上述草稿交付。** 这些不能被说成“已完成听审／已通过最终验收”。无法核实的术语保留原始转写与原声，不猜改；最终字幕校正仍按[字幕规则](./subtitles.md)。
- 核心工作确实整项未做或技术错误未修复时，停在未完成候选并明确缺项；仅用户明确索要该未完成候选时才按其要求交付。**这个例外不适用于只是未听审的、核心工作已经完成的草稿**，不能借它重复要授权。
- Desktop 走原生导出，本地走既有已选生成器；不另写绕过核心剪辑的一次性生成器，不把源时间核查变成第二次重剪。

#### 交付与后续验收

- 在当前片已有 `project.json`／执行回执补实际操作、证据和未决项，不另建状态协议或“已读打勾表”。区分“粗剪草稿已导出并文件核验”“应用打开／播放”“实际听审”“最终成片”，不要只写含混的“剪辑完成”。
- 对用户简述草稿名、时长、已做的剪辑与交接方式；有未听审状态如实用一句话说明。个别需要用户决定的内容只指出具体一句与问题，不倾倒内部切点清单、不要求用户承担未执行的核心剪辑。
- 用户在剪映人工复核／精剪，是草稿交付后的阶段，不是替助手完成缺失的去重或停顿处理。草稿交付后等待定剪视频回流，不自动进入包装。
- 听审只有在实际能力可用且任务需要时执行；用户明确要求“听审通过再交”而当前无法做到时，在开始前说明并聚焦确认，不擅自降低其明确要求。最终成片继续执行字幕、音画及包装验收，代表静帧确认闸门不变。

默认执行入口：[剪映草稿分支](./jianying-editing.md)。调色相关需求的达芬奇推荐与用户选择统一按[素材入口](./intake.md#剪辑与调色工具选择)，不自动切换；达芬奇免费版及既有工程保留，不因选择剪映而删除或升级。

2026-10-19 用户将默认保留目标从 0.1 秒改为 0.2 秒；不改写旧回执，也不自动重剪已存在的候选／草稿。已压到旧目标的时间线仅再次运行 `compress:200` 不会自动恢复停顿；用户明确要求修订旧稿时，须用现有源静音及当次工具支持的恢复能力调整，保留已完成的语义删改，不插入新静音。更早阈值只在核对旧项目时读[更正记录（未随公开版分发）](../public-release-scope.md)。
