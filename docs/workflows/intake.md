# 素材语义分流与预检

仅在收到素材路径、制作请求或需要复查输入时读取。本阶段不加载风格全文、包装库、发布资料或 QQ 操作说明。

## 先判意图，再选流程

本节是素材请求的语义分流权威规则，不要求用户使用固定口令，也不靠关键词命中数量判断。结合当前整句话、最近的明确要求与同片已确认状态，区分“当前要执行的动作”“素材完成状态”和“否定／限定范围”；当前明确要求优先，冲突不能静默猜解。

- **无提示词首次输入默认从头开始**：当前片首次只给素材路径、没有说明动作，或只说“制作／制作成片／做成成片／做成视频”且没有声明已剪好时，默认原素材入口，从剪辑开始；口播进入粗剪，不直接包装，不例行追问“是否要粗剪”。先完成本页预检与工具选择，再进入对应剪辑分支。非口播不硬套口播清稿，按实际对象选择视觉剪辑等流程。
- **同片草稿回流默认包装**：会话已进行到交付本地剪映草稿、由用户在剪映继续编辑的阶段，用户再给该片导出的视频路径且未附新动作时，默认这是剪辑完成、尚未包装的回流视频，进入包装交接，不再次去口癖、删停顿、删句或重排口播。不要求用户再附“已剪好／请包装”。这不是机械地把第二条路径当成回流；同批补充源素材、另一部片、重复发送原素材或草稿文件夹本身，不因此视为已剪视频。
- **二次导出只有一条 B-roll 时直接排版**：同片剪映编辑后的二次导出／回流，包含 B-roll 且只有一个 B-roll 视频时，按[单条 B-roll 回流约定](./packaging-broll.md#二次导出单条-b-roll直接排版)默认视为已按主时间线对齐、剪好的分轨，进入直接排版包装；不要求用户再次声明完成状态，不转回选段／剪辑分支。
- **明确包装或已完成状态优先**：明确说“包装／直接包装／剪辑完成／口播已剪好”等，且没有提出尚需执行的剪辑动作时，进入包装，不重剪；即使这是当前片第一次给路径也一样。
- **剪辑优先**：当前要求“粗剪／先剪辑／剪辑／剪口播／精剪”，或以自然语言要求去口癖、删除重复、压缩停顿、删改片段、调整口播顺序、裁切与编排 B-roll 等实质剪辑动作时，进入对应剪辑分支。只要求 B-roll 剪辑就不擅自重剪口播；只有口播需要剪辑时才进入口播剪辑。
- 按本页判定进入口播粗剪后才加载[粗剪默认规则](./rough-cut-defaults.md)，包含无提示词首次输入与明确粗剪两种入口；回流包装不加载该规则重剪。
- 按本页默认入口或明确要求，需要将风景、旅行等素材剪成以画面为主体的 Vlog 时，进入[视觉 Vlog 剪辑](./visual-vlog.md)，不套口播清稿或把 ASR 当前置；工具仍按下节选择。仅讨论 Vlog、已剪好只调色／包装或只分析时，不启动该剪辑执行。
- **否定与已完成不是剪辑请求**：“不用剪辑／不要粗剪／口播已剪好／剪辑完成了”等表达不能因含有剪辑词而触发重剪。“剪辑风格／剪辑教程”等描述或讨论也不等于要求操作当前素材。字幕校正与音画核查不等于获得删改口播授权。
- **顺序与范围**：“先剪再包装”先剪辑，剪辑验收后才进入包装；“只粗剪／先剪辑，包装以后再说”停在剪辑范围内；“只分析／等我补素材”不自动制作。多个对象分别判定状态，不把口播已剪好等同于所有 B-roll 都无需剪辑。
- **仅实质冲突才澄清**：存在同时要求和禁止同一剪辑动作、素材对象无法确定、回流路径实际仍指向旧原素材等会改变执行结果的歧义时，只问一个聚焦问题；正常首次输入与草稿回流不重复确认。文件名、目录名或预检输出只能辅助识别素材，不能推翻明确语义，也不能仅因名字含“raw／原始”就自动重剪。

回流时“剪辑已完成”是阶段路由假设，不是已完成技术验收的事实；须核对实际导出文件、与当前片的对应关系、字幕及音画同步。剪映草稿生成成功本身不代表用户已完成编辑或已导出视频，也不自动进入包装。人工修改后的实际视频／最终时间线成为权威，不能沿用旧剪辑计划假装字幕仍同步；按[锁定交接](./video-editing.md#4-接回既有-remotion-包装)核验。发现错版、缺轨或无法对齐时先定位具体问题，不擅自改成整条重剪。

### 阶段衔接与命名

- **口播粗剪（初剪）**：AI 清理明确的多余停顿、卡词、失败起句与重复尝试，交付可继续修改的剪映草稿；包含细到帧的切点处理也不等于全片已精剪验收。
- **默认完成点**：原素材口播分支不能停在预检、转写完成或内部 Script。按[粗剪草稿交付条件](./rough-cut-defaults.md#能力检查与交付闸门)完成实际剪辑、技术核验、原生导出及文件回读后直接交付；无须用户再发“导出”口令。只有核心工作缺失／技术错误或用户明确限定范围时才提前停止，未听审不自动等同于核心工作未做。
- **人工复核／精剪**：用户在剪映检查疑点、调整剪点与节奏等；是否称精剪取决于实际工作，不因导出了一条 MP4 就自动宣称做过精剪。
- **定剪视频（未包装）**：用户确认当前剪辑可交给包装的导出视频；“定剪”表示本次包装所依据的剪辑版本，不代表已经包装或最终成片。后续剪点变化须重新核对字幕与包装同步。
- 同片沿用已有项目登记与交付记录，交付草稿时记录草稿位置及等待用户编辑回流的状态；收到回流后登记实际导出视频与核验结果。项目登记仍用仓库相对路径，不新造第二份项目状态协议。新会话先查当前片记录，不单凭对话里第几次出现路径判断；没有项目线索且无法判定时才聚焦澄清。
- 阶段路由约定不是后台文件监听器；用户给出回流路径后可读取核验，不宣称已经自动发现任意导出目录中的新文件。
- 用户暂停、只问原因／工具配置或要求梳理规则时，按本次对话范围解释或维护文档，不顺手继续修改时间线／导出；明确恢复后沿用已有工程与成功结果，不从头重跑。

### 语义示例

| 用户表达 | 应选分支 |
| --- | --- |
| 当前片首次只给素材目录 | 从头开始 → 预检／工具选择 → 对应剪辑；口播默认粗剪 |
| 当前片首次说“这个素材制作成片／做成成片” | 从剪辑开始，不跳过剪辑直接包装 |
| 同片已交付剪映草稿，用户编辑后只给导出视频路径 | 定剪视频回流 → 核验／字幕交接 → 包装，不重剪 |
| 同片二次导出回流含 B-roll，且只有一个 B-roll 视频 | 默认已按时间线对齐并剪好 → 直接排版包装，不重新选段或剪辑 |
| 草稿交付后补充另一段原素材／另一部片的路径 | 按当前对象与明确状态判断，不机械当作回流视频 |
| “剪辑已经完成，帮我包装” | 包装，不重剪 |
| “不要剪辑，直接做成片” | 包装，不重剪 |
| “先粗剪／帮我剪辑一下” | 剪辑，不提前包装 |
| “把口癖和重复句去掉，再做成片” | 口播剪辑 → 验收 → 包装 |
| “口播剪好了，把录屏里的等待剪掉再包装” | 只剪 B-roll → 验收 → 包装 |
| “只粗剪，包装以后再说” | 仅剪辑 |
| “这种剪辑风格可以吗，先只分析” | 仅分析 |

## 先做轻量命名分流

本节是素材角色与是否进入视觉选段的命名规则权威位置；只看当前输入的目录名和视频文件名，不为识别角色先读 B-roll/Vlog 方案、抽帧、转写或启动模型。先执行 `npm run media:classify -- --input "<当前路径>"`，现有素材预检也会返回同一 `mediaRouting`。

| 当前输入 | 角色与后续 |
| --- | --- |
| 两个子目录，如 `口播/` 与 `broll/`，文件本身未命名 | 按所在目录分组，口播与 B-roll 分开 |
| 同目录里，只有部分视频文件名标了 `broll` | 这些是 B-roll，其余未标记视频按口播 |
| 单个目录，目录和视频名均无 `broll` 标记 | 所有未标记视频按口播；即使有多条、叫“风景/录屏”，也不据此启动配画面，不加载其规则 |
| 输入目录本身叫 `broll`，内部是相机默认文件名 | 作为 B-roll 库，不将其中最长视频猜成主口播；缺少主口播就不启动语音覆盖 |
| 只给一个视频文件 | 仅处理该文件，不扫描同级其他素材替用户扩展范围 |

`broll / B-roll / b_roll / b roll` 大小写不敏感，可与数字、中文或分隔符相接；不把 `broller` 等其他英文单词误识别。文件名的明确角色优先于父目录，目录取最近的明确角色；同名同时明确“口播”和 B-roll 时报告冲突，不静默猜。命名扫描只覆盖当前根及两层子目录；未覆盖目录显式列出，需要时缩小输入或在命名命令用 `--depth` 扩展，不能声称已查全。

**当前明确要求和已确认角色仍优先**：明确视觉 Vlog 不受“未标记默认口播”限制，命名命令可用 `--mode vlog`；明确只口播/不配画面、只校字幕、只调色或只分析时不因存在 B-roll 库扩大动作。命名结果只决定角色与候选路由，不授权重剪、上传或执行。用户明确指定未标记素材为 B-roll 时先记录该指定，不要求用户改名；当前自动准备入口仍按命名筛选，不能为了绕过它谎称素材是 Vlog，须补明确角色适配后再批量执行。

无 B-roll 的口播停在既有口播/包装入口，不读 `broll-selection.md`、`visual-selection.md` 及其执行细节。发现 B-roll 且当前动作需要选取/配画面时，才进入[口播配画面](./broll-selection.md)。单独的视觉 Vlog 按[视觉 Vlog](./visual-vlog.md)进入，不预读口播分支。

文件名中的地点、对象、动作和编号可用于初筛、搜索与浏览优先级，保留原名作为线索；它不证明实际画面、地理身份、拍摄顺序或精确入出点，最终仍须看源素材核对。

## 剪辑与调色工具选择

本节是工具选择的权威规则，与上面的动作／范围判定分开执行：

- **其余默认剪映**：进入剪辑且用户未指定工具、没有下述调色需求时，走[剪映草稿分支](./jianying-editing.md)，按本机已验收语音链使用本地生成器或 Desktop。不例行重问已选软件，不加载达芬奇细节，也不因机器是新 clone 就提前部署未用工具。
- **调色需求先推荐、再选择**：客户提出旅行 Vlog、旅游、风景／自然景观等可能需要调色的制作需求，或任何题材的明确调色、色彩统一、白平衡／曝光校正、Log 素材还原等需求时，主动推荐达芬奇，并让客户选择达芬奇或继续剪映。示例：“这类旅行／风景素材建议用达芬奇处理调色，也可以继续用剪映。你希望选哪一个？”只有选定后才进入对应执行分支，不把推荐当作切换授权。
- **结合语义，不按词抢跑**：单纯讨论 Vlog、文件名含“风景”、只校字幕、明确“不用调色”等不因此触发软件选择。用户已经明确选择剪映或达芬奇时沿用该选择，不重复询问；未回复选择时不擅自进入任一工具执行调色。
- **不扩大任务范围或能力声明**：工具选择不授权重剪已剪好的口播、不自动进入包装，也不授权安装、购买或界面操作。已剪素材仅要求调色时保留剪辑结构；选择达芬奇后读[达芬奇独立操作包](./resolve-editing.md)，只有安装或环境故障才进入其部署链接。现有执行器的剪辑测试不代表调色功能已实现或通过验收，调色操作须按本次能力核查与实际画面验收。

## 再执行当前分支

1. 有可访问素材路径时，在项目根运行 `npm run inspect:input -- -InputPath "<路径>"`，用于识别媒体和字幕。`productionIntentDetected`、`nextGate` 等预检字段只是技术提示，不能覆盖上面的语义判定；剪辑或仅分析请求不能因发现视频而自动进入包装。
2. 首次无提示词输入进入剪辑分支；同片草稿回流或明确包装输入识别到视频后，核验当前文件与字幕，再启动现有包装流程，不反问“要做什么”。涉及本页调色相关需求时先完成工具选择及所选调色阶段，不重剪已剪好的口播。剪辑分支按本页工具选择规则默认进入剪映，只读取当前对象、相关字幕与音频；ASR／计划准备／锁定交接才读[最小流水线](./video-editing.md)对应阶段，计划字段查[最小协议](./editing-contract.md)。达芬奇仅用户选定后加载其执行章节，实际能力状态按需查[改造状态](./context-loading-plan.md)。数据工具不能替代真实剪辑，未接入的能力不得伪称已实现，也不得用包装替代用户的剪辑请求。
3. 目录名作为默认片名；根据文件名语义、媒体时长和实际内容识别主视频、B-roll、独立音频与时间轴字幕，登记来源和同步关系。不把预检猜测当作已经完成的音画对齐。
4. 成片任务按片名运行 `npm run review:project -- -Title "片名" ...`，复用同名项目；登记细则见[审片目录规则](../../remotion-clone/review/workflow-flash/README.md)。单纯系统文档维护不新建审片项目。
5. 制作／剪辑涉及字幕时先按[字幕规则](./subtitles.md)校对权威时间轴；只有进入包装分支时才读[内容规划](../02-content-planning.md)。无时间轴先建立并告知；字幕未决项不能进入最终成片。
6. 代表静帧、确认闸门、长片分段与后续制作只在进入包装时读取[制作规范](../03-remotion-production.md)，不在预检重复维护参数。

分流规则与数据协议不等于已经接入达芬奇。首次默认剪辑与明确剪辑请求按需核对相应实现与能力边界；包装输入不为重剪加载剪辑计划与执行器，草稿回流只读取必要交接章节。尚待实施的集成步骤见改造状态，不由本规则自动启动。
