# 修改与验证

仅工程修改或验证任务读取，不是所有素材制作会话的前置文档。

- 修改保持聚焦，不重写无关历史实现；不为减少上下文删除历史证据。
- 代码改动完成后运行最小相关测试。Remotion路径、组件 API 或构建配置变化时，运行根目录 `npm run remotion:typecheck`，并验证受影响的实际调用；剪辑/素材工具按对应模块运行测试。
- 包装组件 API 改变时核对当前组件、实际使用方和方案文档；索引格式变化核验当前有效链接与消费者，不为归档项目追加验证要求。
- 归档项目不参与当前安装、构建与验收；只有用户明确要求恢复或维护时才读取归档内说明，并重新核查它与当前实现的兼容性。
- 纯 Markdown／技能路由修改且未改可解析的方案索引／props 格式时，核验相对链接、规则迁移覆盖、技能 frontmatter 和实际任务路由；不为文档修改重复渲染视频或安装依赖。
- 类型、代码、时间轴和渲染错误直接排查；画面质量判断才查关键帧或短视频，视觉验收按[制作规范](../03-remotion-production.md)。
- 如实区分文档、静态、动态和音视频验收，只报告实际验证结果。

新机接入工具维护先运行 `npm run setup:test`，并在不带 `.codex/`、`tools/`、`node_modules/` 的克隆副本验证入口与模拟测试。覆盖自动探测、用户显卡粗选、未知推荐 Desktop、本地优先、明确选择优先、不覆盖已有配置、不把文件存在当连接／推理通过；安装器／实际模型／真实新机验收另记，不用模拟测试冒称完成。文档新增入口还须检查到本地／Desktop 分支的路由及原生产闸门未丢失。

## 文档入口调整的最小核验

仅修改路由、拆分操作/部署/历史文档时执行，不增加制作任务的常驻前置：

1. 核验被修改文档的本地链接、章节锚点以及指向迁移章节的入链；旧锚点保留明确跳转或同步修正入链，不静默改读整篇。
2. 对照迁移前文本检查规则去向：操作所需前提、异常停止、权限、校正/确认闸门和验收必须仍在操作包或其明确必要入口；历史证据保留，不以精简为由删除。
3. 按用户意图做小范围路由走查：首次纯口播、同片剪映导出回流、已有字幕仅校正、默认 ChatCut 转写、ChatCut 连接／权限故障、用户指定 Desktop、用户已选达芬奇、代表静帧未确认。既检查不进入无关分支，也检查必要约束没有缺失；不要为走查真的转写、安装或渲染。
4. 读取完整/依赖完整与任务执行完整分开核验。至少对照以下反例，不能把不同失败层级并成“未完成就都不导出”：
   - 句级SRT可用但停顿阶段未执行：核心工作未做，不能仅凭生成器成功交付成默认粗剪成果。
   - 语义剪辑、停顿及切点技术核验已完成，仅无真实听审能力：继续导出并核验可编辑草稿，如实说明未听审，不追加导出授权。
   - 一次 `create_project` 清单缺项：先按连接包有界重试；写调用结果不明先回读，不盲建第二个工程，也不立即让用户手建。
   - 用户说“等等”后追问原因／要求理顺规则：仅解释／改文档，不恢复时间线写操作或导出。
   - 用户明确要求听审通过再交：无能力须提前说明，不能以草稿分级规则擅自覆盖其要求。
5. 以上仅为文档逻辑走查，不是运行时拦截、真实听审、实际导出或模型行为验收。文档修正不自动清除现有片的未决项，不把旧候选回填成已交付；源码未改时不宣称桥接已具备自动重试。
