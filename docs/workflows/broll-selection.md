# 口播配画面：从 SRT 语义到源选段

仅在用户要求补画面、选取/编排 B-roll 或维护此能力时读取。普通口播粗剪不自动插入素材，口播已剪好的状态保持不变。它与纯视觉 Vlog 共用[长素材选段](./visual-selection.md)，但不共用语音驱动的故事骨架。

## 当前能力，先分清楚

| 部分 | 实际状态 |
| --- | --- |
| 标签和说明检索 | `video_editing/broll_adapter.cjs` 已有文字召回；不读取视频，不自动发现入出点 |
| 指定选段的覆盖 | 现有编译与草稿后端已有源起点、目标区间和另轨静音覆盖的基础代码 |
| 长视频自动看懂、最佳片段判断 | 可分批准备概览/精看证据，由助手实际观察形成审阅；未新增自动视觉模型或无人值守语义闭环 |
| 审阅后候选计划 | 已有内部清单、源/字幕绑定与合法区间组装，生成既有协议；声明格式通过不证明语义正确 |
| 剪映实际效果 | 历史口播实测没有 B-roll；有代码不等于这一分支已完成真实应用内验收 |

不把旧文字检索命令改名成视觉剪辑，不导入参考仓库或模型。角色先按[素材命名分流](./intake.md#先做轻量命名分流)，无标记 B-roll 的普通口播不加载本页；实际准备证据或组装计划才读[本地执行入口](./visual-selection-execution.md)相关步骤，只报告实际完成的能力。

## 1. 先明确口播时间轴

- 字幕必须先按[字幕规则](./subtitles.md)校正。保留正文原意和来源，不把规划摘要写回字幕。
- 如果口播已经删段，用与当前剪后版本一致、已核对的字幕安排覆盖；仍在粗剪阶段时可先做语义候选，但目标位置标为暂定，不能把原始 SRT 时间直接填进剪后时间线。
- 现有单源协议可依据已确认删段得到 `captions-edited.srt`，仍须核对实际音画。人工调整、重排或多源口播不能靠总偏移猜目标时间；当前版本与映射不明时停止写入。
- 找当前完整语义及必要相邻句，不逐条字幕机械插一镜。“不用 X，而是 Y”不能因为搜到 X 就配 X 的画面。

## 2. 把语义转为画面需求，而非照抄关键词

对确实有配画面价值的语义段，记录原字幕编号/版本、目标时间窗、观看任务、需要出现的对象与动作、不能误导的事实，以及是否需要保留说话者画面。

| 需求 | 选画面方式 |
| --- | --- |
| 证明具体事实/动作 | 画面需真实显示对应事实；普通相似场景不能冒充当时当地 |
| 说明过程或使用方法 | 选动作顺序和结果看得清的区间，而非仅有同一物体的静态画面 |
| 建立语境/环境 | 可选与主题确实相关的环境镜头，不必把每个名词都字面表现 |
| 抽象感受或比喻 | 明确是示意/氛围，不伪造证据；找不到恰当画面可保留口播 |

同一完整意思可以跨多条 SRT；需要时一个窗口也可以容纳多个有关系的镜头。SRT 只限定语义和时间参考，不要求覆盖整个句子，也不要求切点严格等于字幕起止。

## 3. 查候选并选出真正可用区间

按[共用选段规则](./visual-selection.md)查已核验的源索引。已有文字搜索只是粗筛；对候选查看连续画面，记录它满足需求的事实、问题区间与可用入出点。

比较时先排除：来源不明、语义相反、动作未发生、素材不足、关键内容被裁掉或字幕冲突等实际问题。然后比较动作清楚程度、构图、与前后画面的连接、重复程度和风格；不以单个未经校准的“AI 综合分”决定最终使用。

长素材无用的部分不进入使用区间，但原片保留；不先把所有所谓废片永久删除。对照镜头仍无确切依据时，状态是待复核或无匹配，不是自动选择得分最高的那条。

## 4. 将源时间与目标时间分开

在当前片 `broll-selection.md` 中维护需求与使用记录：当前口播/字幕版本、语义窗口、共用候选编号、源使用区间、目标覆盖区间、采用理由、待核项。证据只引用 `visual-selects.md`，不复制完整素材描述。

示意：假设剪后口播的 42–47 秒需要海浪撞礁石，实际已复核素材的 192–197 秒可用，则基础 1 倍速覆盖为：

| 参数 | 含义 | 示例秒数 |
| --- | --- | ---: |
| `start` / `end` | 剪后口播时间轴上的覆盖范围 | 42 / 47 |
| `source_start` | B-roll 原素材里的使用起点 | 192 |
| 推导源末端 | 源起点 + 目标时长；仅适用于此基础 1 倍速模式 | 197 |

以上数字仅说明两条时间轴，不是实际素材分析结果。最终写入需按帧率量化并回读边界，不能认为任意秒数都落在真实帧上。

写入现有[最小剪辑协议](./editing-contract.md)前须满足该协议的限制：单口播源、同帧率、单层互不重叠覆盖、正常速度、源区间足够且口播总长不变。只生成既有允许的字段；不把候选评分、审阅状态或新结构塞进执行协议。

多源口播、环境声混入、变速、交叉淡化等超出当前基础模式时，先核对执行器适配，不能把需要新能力的计划静默降级成静音硬切。已声明的用户必用内容不能被自动检索忽略。

## 5. 看合成结果，不只看选中的素材

- 试听口播，核对画面是否在对应意思成立时出现，不能提前揭示或与否定句相反；需要口型、表情或操作展示的区域不能随意覆盖。
- 检查覆盖前后回到口播是否突兀、连续素材是否重复、裁切是否伤及主体、原烧入字幕是否冲突。候选静帧通过不等于覆盖后节奏成立。
- 按用户选定的工具生成新审片草稿，保留原片和前一版本。实际回读轨道、源区间、音量、目标位置与时长，再打开看听验证；不能只用 JSON 合法证明应用可用。
- 无合适素材保留口播；不为了“配满”自动搜网图、生成视频、循环、冻结或拖慢素材。新增生成/上传等按用户明确范围处理。

剪辑阶段的软件执行按[剪映分支](./jianying-editing.md)或用户已选的达芬奇分支；包装阶段改走下节，不加载工程执行。无真实应用内验收时不称完整剪辑流水线通过；包装确认闸门不变。

## 包装阶段直接选段分支

先按[包装 B-roll 衔接](./packaging-broll.md)复用已剪好、独立导出并与口播对齐的 B-roll；它仍做原包装的对齐核验、黑段处理、裁切、构图与 ROI，不重复语义选段。

只有未处理原素材或本次新增需求没有合适选段时，才读本页第 1–3 节与[共用视觉选段](./visual-selection.md)当前步骤。需求与目标位置以当前定剪视频对应的权威校正版字幕为准，不回退到原素材 SRT，也不要求为包装创建旧口播剪辑计划。

选好后直接给原包装提供源区间/物理短片，执行细节按需见[包装执行](./packaging-broll-execution.md)第 2、3 节。此分支不生成剪映工程、不重剪口播、不自动修改 Composition；原字幕与代表静帧确认闸门仍有效。
