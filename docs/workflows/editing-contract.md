# 最小剪辑协议

本机已选本地帧编译／字幕重映射分支（含新机接入验收选定）使用同片项目的 `edit_plan.json`；Desktop 已选分支直接保存其源引用和真实时间线快照，不强塞此单源协议。本地流水线只用 `edit_plan.json`，不扩展专业 EDL。普通已剪口播包装无需创建计划。

```json
{
  "source": "remotion-clone/public/片名/source.mp4",
  "cuts": [{"start": 12.5, "end": 15.5, "reason": "经音频核对的重复表达"}],
  "broll": [{"start": 30, "end": 40, "source": "remotion-clone/public/片名/effect.mp4", "reason": "匹配当前口播语义"}]
}
```

## 仅这些必要约定

- `source` 是口播原素材的仓库相对路径；所有源文件保留。切点以秒表达，区间统一 `[start,end)`。
- `cuts` 是**原素材时间轴**的删除区间；`broll` 是**删除完成后的口播时间轴**的画面覆盖区间。不延长口播，不混入第二条人声，不自动改速。
- B-roll 可选 `source_start` 表示其原素材起点，默认 0。可选 `burned_in_subtitles` 声明画面已有字幕；未声明表示待核验，不能默认当作无烧入字幕。
- 第一版单口播源、单层无重叠 B-roll、固定帧率／同帧率素材；短素材不自动循环，混合帧率、变速、重排、独立音频要明确适配，不静默猜测。帧率近似或 VFR 需先核验／显式转码和对齐。
- `reason` 必填。AI 在读取完整权威字幕及必要音频后给建议，不把 SRT 空隙直接当作静音、不根据用户审片定位时间码直接下刀。
- 词级 JSON 只有经过格式、单位、完整性与音频对齐验证才支持句内切点。当前 SRT 自动重映射要求整条字幕完整保留或整条删除；切穿条目必须停止，不能复制半句或摘要代替。
- SRT 整数毫秒与原视频帧边界序列化产生的至多 1 毫秒差异，只在派生字幕中约束到保留片段边界；原件不改，较大的切穿仍阻断。此容差不是允许删掉词语或免做音频核对。
- 软件无关的公共计划始终只有这一份；帧列表、校验哈希和执行输入是内部派生数据，不增加公开时间映射协议。

单源计划校验与帧编译以 `video_editing/editing.cjs` 为准；工具选择按[素材入口](./intake.md#剪辑与调色工具选择)，默认走[剪映草稿分支](./jianying-editing.md)。ASR、计划准备、选定后的达芬奇执行与包装交接边界见[流水线对应章节](./video-editing.md)，不为默认剪映加载达芬奇执行细节。

## 旧版保留，不自动混用

此前 `edit-plan.json`（连字符）的复杂 v1 协议和工具保留为[历史数据协议](./editing-contract-v1.md)。`edit:validate` / `edit:prepare` / `edit:test` 仍只服务它，不冒称兼容新格式。新流水线使用 `video:prepare` / `video:test`；旧项目不迁移、不覆盖历史证据。
