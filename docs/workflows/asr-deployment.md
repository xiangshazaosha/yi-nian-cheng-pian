# ASR 部署选型：新机本地优先

新机／换机已进入[接入与安装](./new-machine-setup.md)、本地部署或选型维护时读取；已配置的日常转写不反复部署，Desktop 故障也不自动触发。当前只提供本地 ASR 与 ChatCut Desktop 两个语音方案；原有程序、模型与证据保留，不自动卸载或清理。

## 1. 项目决策

- **新机优先本地 ASR**：进入授权部署后先检测／粗选、评估本地，条件满足则协助安装和实测，不重复要求用户指定同一选择。不满足才推荐并协助安装 Desktop。明确选择或已有可用环境优先；安装不等于验收，原机不自动切换。

- **质量优先**：本地 Whisper 默认以多语言 `large-v3` 建立首测基线。turbo 仅在用户明确选择快速初稿／速度优先时评估；不因配置不足自动降级到 turbo、small、量化模型或 CPU 慢跑。
- **配置不足就仅推荐 ChatCut Desktop**：兼容性、资源、速度、样本质量或稳定性不满足时不强行部署本地。保留证据并说明，用户选择后接回 Desktop 安装，不自动上传，不靠反复安装／社区补丁强行接入。
- **未知可按显卡粗选**：先检测；受限时只问用户显卡型号，允许据此给初步方案，必需资源／驱动在部署中由 Agent 补核。型号也说不清则推荐并在授权后带装 Desktop；不能把未知说成显卡不足或承诺 GPU 可用。
- **推荐不等于执行授权**：检测与推荐后，只有用户进入部署任务才安装。ChatCut 被选为可用通道也不等于自动授权上传任意素材；上传范围、身份与认证仍按该分支核验。用户禁止上传且本地不合格时报告阻塞，不绕过限制。
- 检查器能输出初步路线，但不是自动硬件调度器或无人值守安装器；实际安装、来源核验和样本测试由当前 Agent 按接入流程执行。

## 2. 需要检查的配置

显卡型号足以做初步推荐，但**不能只按型号或总显存签署部署通过**。检查用户当前电脑，不把作者电脑或旧通过记录当新机证据；下表由 Agent 按必要性补核，不要求用户先提供整套专业报告。

| 检查项 | 判断内容 |
| --- | --- |
| 系统与架构 | Windows／Linux／macOS、版本、x64／ARM64；目标是否为虚拟机、容器或受限主机 |
| 加速设备 | 准确 GPU 型号、厂商与架构；独立／共享／统一内存；当前实际可用显存或内存，不只看标称总量 |
| 驱动与后端 | 目标后端的官方设备与系统支持、驱动／运行库版本；容器内设备透传与实际可访问性 |
| 内存与 CPU | 可用系统内存、解码与音轨准备能力、CPU 指令支持；共享内存设备不能把同一份容量重复计算 |
| 磁盘 | 模型、依赖、完整音轨、任务证据、临时文件与并发工作目录所需空间；可写目录和持久化能力 |
| 工作负载 | 语言、术语、音质、素材时长、并发数、其他视频／模型任务竞争、用户可接受的完成时间 |
| 运维条件 | 安装权限、网络／下载条件、维护成本和素材隐私要求 |

不设一个跨引擎通用的“显存达到 X GB 就能部署”阈值。模型文件大小不等于推理显存，其他实现的显存表也不能直接套用；按选定版本／模型／精度／并发建立预估，再用真实样本确认峰值和余量。首次从单任务开始，不按显卡标称容量直接承诺并发。

## 3. 按配置推荐后端

当前换机执行器只接入 Windows x64 的 whisper.cpp Vulkan。下表区分可评估设备与未适配平台，不把其他引擎当作已接入第三路线。只核查当前后端的官方支持和必要依赖。

| 目标配置 | 推荐方向 | 通过条件 |
| --- | --- | --- |
| 当前 Windows + AMD RX 7700 XT | whisper.cpp + Vulkan | 按[本地部署与环境修复](./local-whisper-setup.md)核验驱动、真实 GPU 绑定、资源与质量 |
| 其他 Windows x64 AMD／Intel GPU | 评估 whisper.cpp + Vulkan | 准确设备及驱动受支持并实测；不能按厂商继承原机结论，核显也不自动算合格独显 |
| Windows x64 NVIDIA GPU | 优先评估已接入的 whisper.cpp + Vulkan | 查当前官方支持和驱动；CUDA／faster-whisper 未接入当前启动器，不能写个配置就宣称支持 |
| Apple Silicon／其他未适配平台 | 本地启动器／Remotion 平台包待适配；核查 Desktop 平台能力 | 不装未适配 Metal 引擎冒充全链；Desktop 有下载包不等于整个仓库已适配 |
| 无可用加速设备／资源或性能不达标／不允许所需依赖 | **推荐 ChatCut Desktop** | 不自动跑 CPU 或降级模型；无法识别显卡时同样推荐，不谎称硬件不足 |

当前 RX 7700 XT 已完成资源探测与 GPU 技术短测，**正式字幕质量与长片稳定性仍待验收**，当前主机运行入口见[运行配置](./local-whisper-asr.md#输入与运行)。历史驱动故障或构建证据仅在排错时读[部署记录（未随公开版分发）](../public-release-scope.md)。后端适配与中文识别质量是两道独立闸门；技术短测通过不等于字幕可用，也不代表其他机器已通过配置检查。

官方支持依据按部署时版本复查：[whisper.cpp 后端与平台](https://github.com/ggml-org/whisper.cpp)。上游支持某后端不等于项目已适配，不能替代真实素材测试。

## 4. 统一验收与部署记录

1. 先只读探测，形成必要摘要；不把整台机器硬件清单、驱动长日志或无关个人信息带入上下文。
2. 记录选定环境、引擎及版本、后端、模型及哈希、语言／精度／并发配置、资源预估；未知项列出，不用猜测补齐。
3. 通过兼容性与资源预检后，进入用户指定的部署任务，再执行选中分支的安装与短样本验收。默认 `large-v3`，选型确认不能绕过字幕校正与原素材时间轴要求。
4. 以 30～60 秒含术语、停顿与重复表达的真实样本核对 GPU 实际绑定、文字／时间轴质量、耗时、峰值显存和系统内存；再验证较长素材与实际目标并发，不能把短样本速度线性外推成生产保证。
5. 只有稳定运行且达到该任务的质量、时效及资源余量要求，才登记“可用”。OOM、CPU 偷跑、关键漏识别或漂移不能当作通过；无法满足则仅 ChatCut。保留原模型和测试依据，不通过无声更换模型掩盖失败。
6. 部署记录至少包含环境标识、检测时间、实际设备／可用资源、系统／驱动、组件来源与版本、模型／参数、实测样本／峰值／速度／质量、结论及证据路径。机器变化、驱动／后端／模型更新、并发提升或长期失败时重新评估，旧记录不直接移植。

本机安装仍按[项目软件目录](../../tools/README.md)；部署证据放选中工具的独立目录，不写入常驻技能。长期文档与登记使用仓库相对路径，运行时绝对路径由环境配置提供，不硬编码当前盘符。
