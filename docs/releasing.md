# 源码发布与后续维护依据

本页只在明确发布、许可或维护版本时读取，不是日常制作的前置。许可证、声明和检查均不替代权属调查或第三方授权。

## 单一来源与两个用途

日常工作仓库保存制作记录、历史证据及未发行内容；公开仓库只保存按白名单导出的源码快照。不是手工维护两套核心代码。公开发布不自动改动本机素材、已装环境或其他未提交工作。

公开仓库：xiangshazaosha/yi-nian-cheng-pian。私有备份和本机映射记录不进入公开源码。首发使用独立新 Git 历史，不能只另开分支便以为原私有历史不可见。已有公开历史后，正常快进提交更新，不重新初始化，不强推，不删除旧 tag。

## 发布材料的单一来源

- 根 LICENSE：与方寸 2.0 正文相同；NOTICE 只写一念成片实际权利范围。
- THIRD-PARTY-NOTICES.md：独立依赖及安装边界；docs/licensing.md：视频场景，二者不改变正文。
- release/export-policy.json：精确文件/目录白名单及公开覆盖模板；新增文件默认不进入发行包。
- release/templates/：公开版入口和脱敏替代文件；必须保留核心代码、必要脚本和配置，不能只留下说明或空壳。
- release/export-manifest.json：由导出器生成的逐文件 SHA256、内容摘要与源提交；不包含私有路径清单，不含时间戳，固定源提交应生成相同结果。
- CHANGELOG.md、docs/releases/：每版变更、实际验证及已知未验收能力；本机 tools/releases/ 下的回执记录工作源提交与公开提交/tag 的对应关系，不提交凭据。

## 每次发布步骤

1. 明确用户授权、归属、仓库、版本与可见性；查看 Git 状态，只提交本次相关文件，禁止顺手纳入正在制作的旧片。选择已提交的源码 ref，不从整个工作目录打包。
2. 检查新增/修改文件的权属、贡献者明确授权、第三方原许可、网络行为及分发义务。许可更改保存旧版，不追溯撤销有效授权；依赖升级核对实际版本，不静默运行更新。
3. 更新 CHANGELOG、发行说明、export-policy 的版本及必要模板。运行发布工具的单元测试，再从已提交 ref 导出到不存在的新目录：

       python -m unittest discover -s scripts/release -p test_*.py
       python scripts/release/release.py export --ref HEAD --output tools/releases/待发布版本
       python scripts/release/release.py check --root tools/releases/待发布版本

4. 在独立发行副本测试：setup:test、edit:test、asr:test、video:test、visual:test、packaging:broll:test；包装入口/依赖变化还须 npm ci 及 remotion:typecheck。只在发行副本安装，不重装日常环境。
5. 缺实际新机或账号时明确标记未验收。首次无媒体 PublicSmoke 做技术入口检查；它不授权整片制作，不代替真实 ASR、Desktop 连接、听审或最终成片验收。记录具体命令、结果、执行版本及边界，不把待做检查写成通过。
6. 更新发行证据后提交工作源，重新导出并复验；禁止人工修改导出文件而不回写其来源/模板。逐项审阅清单和省略链接，必要规则不得因脱敏丢失；密钥模式未命中不等于完成隐私/权属认证。
7. 正式推送前用实际 Git ref 枚举整个待公开历史，确认只有发行源码；本机工作仓库的远端保持私有。首次公开库先私有创建、检查实际远端 main 和 LICENSE/清单后再切公开；以后普通快进更新。检查远端最新提交是否与预期一致，遇到别人更新先停止处理，不强推覆盖。
8. 推送后验证实际可见性、main、tag 及 Release，记录本机映射。提供匹配版本的免费源码下载；遵守 LICENSE 中提供期间及最后一次提供后三年的可获取义务。回滚用修复提交/新版本，不删除过去已发版本或把法律文件悄悄换掉。

## 公开贡献的回流

公开库收到 PR 时先审查来源、贡献者明确许可和测试，再在工作源重放与制作数据无关的改动，更新模板/白名单，重新导出比较。公开库和工作源都不能作为盲目覆盖另一边的理由。非破坏性同步前记录双方基线；不直接将私有 main 合并进公开 main。

## 发布停止条件

发现密钥、个人/客户内容、未授权依赖副本、来源不清代码、未标明的许可变化、失效的必要规则链接、缺核心源码、清单漂移或测试失败时，停止公开，不用免责声明代替修复。若发现已公开凭据先撤销/轮换并评估影响；不能只删当前文件声称已收回历史。
