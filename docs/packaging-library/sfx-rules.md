# 动态音效使用规则

> 公开版不附送音效；下列旧文件名及默认增益只是历史预设，不是本机已有素材或新素材的验收结论。


> 本文档定义包装库所有音效的使用规则。组件/动效方案文档只引用本文档，不重复写规则。
> 运行素材统一从 `public/sfx/` 与 catalog 引用；[`sfx/`（未随公开版分发）](../public-release-scope.md) 仅保留历史通用素材副本，新用户音效不往此处重复复制。

用户提供的处理好素材直接与历史音效放在 `remotion-clone/public/sfx/`，通过[统一目录索引](../../remotion-clone/public/sfx/catalog.json)检索；来源、处理和引用规则见[用户音效资产](./user-sfx-assets.md)。用户要求不保留的外部原件不复制入项目；库索引不等于统一响度或平台合规证明。

| `pop.mp3` | 多文字插入（间隔任意） | ✅ 使用 |

`swoosh.mp3` 和 `ding.mp3` 保留在 `theme.ts` 的 `SFX` 常量里供未来扩展，当前所有段代码不传入。

## 响度校准

内置素材的源响度并不一致：`tick.mp3` 明显轻于 `pop.mp3` 和 `shimmer.mp3`。为避免口播把提示音完全盖住，当前默认增益为：

- `HighlightTag + pop`：0.65
- `StepList / StepFlowBar + tick`：1.0
- `shimmer`：0.65

不要把所有音效统一设为 0.3；这会让 tick/pop 在完整口播混音里接近不可闻。若替换音效文件，应重新测量响度并同步 `theme.ts` 的 `SFX_VOLUME` 与组件默认值。

### 相对口播响度校准（跨风格硬规则）

音效是否足够大，必须以**同一时刻的口播响度**为参照，不能只看素材自身音量、增益百分比、整片 LUFS 或导出文件有没有削波。

- 口播是 `0 dB` 听觉参照。先保留独立的 `voice bus` 与 `sfx bus`，在有人声的真实事件窗口内比较两者，不能只在静音处试听音效。
- 每种类别至少抽查 3 个代表事件：片头、片中、片尾各一个；连续列表还要检查密集组中间的事件。
- 短音效优先比较事件附近约 `200–500 ms RMS` 与瞬态峰值；整片 Integrated LUFS 只能用于最终节目交付，不能证明某个 Tick、Snap 或 Sweep 相对口播足够清楚。
- 默认听觉目标以“普通播放器音量下，不刻意寻找也能听见，但不遮住当前字头”为准。可先使用以下相对范围，再以人耳微调：
  - `UI_TICK / DIGITAL_BLIP`：约低于邻近口播 `8–14 dB`；
  - `UI_SNAP / DIGITAL_SWEEP / SHORT_WHOOSH / ERROR_BLIP`：约低于邻近口播 `5–10 dB`；
  - `MICRO_IMPACT`：约低于邻近口播 `3–8 dB`。
- 若事件恰好撞在爆破音、重读字或口播峰值上，优先把 SFX 前后微调 `1–3` 帧，或使用局部自动化；不要为了听清音效把整条口播压低。
- 最终 `loudnorm`、限制器或节目级归一化之后必须重新试听，因为总线处理可能改变瞬态的主观可辨识度。

“提高 50%”是线性振幅乘以 `1.5`，只相当于约 `+3.52 dB`；再乘 `1.38` 约增加 `+2.80 dB`，两次合计 `2.07× ≈ +6.32 dB`。百分比不能直接等同于“人耳大了多少”，以后应优先报告**相对口播的 dB 差和试听结论**。

## 背景音乐与口播共存

背景音乐是节目级底床，不跟随单个组件触发，也不替代 pop/tick/shimmer：

- Remotion 先完成“口播 + 短音效”的逐帧混音，生成 `out/full-video-sfx-mix.mp4`
- `scripts/render-full.ps1` 在后期加入 `public/music/ai-home-ambient.wav`
- 音乐先做 `highpass=80`、`lowpass=8000`，并在 2.5 kHz 附近衰减 4 dB，为普通话辅音和咬字让位
- 口播节目轨通过 `sidechaincompress` 自动压低音乐；短暂停顿时音乐自然回升
- 总混音最后统一到 -16 LUFS；不得仅靠把口播整体拉大来压住音乐
- 后期只允许 `-c:v copy` 复制视频流，避免为了加音乐再压一遍画面

本片音乐由 `scripts/generate-bgm.py` 确定性生成，属于项目自制素材；若换成外部音乐，必须保存可商用授权凭证并重新校准音乐增益与旁链阈值。

## 节目级后期动效音效

当用户明确要求“按整条成片的视觉动作补音效”时，可以在 Remotion 画面锁定后进行节目级后期混音，不必为了加声音重新渲染画面。此模式与组件内 `sfxSrc` 并存，但必须遵守：

- 只给**大构图进入、快速交接、操作点击、节点完成、结果确认**等可感知事件配音；普通字幕、常规标题和每个小位移默认无声。
- `swish` 可作为大构图或成组卡片横向进入的轻扫声，但不能给每个剪辑点都加，也不能把普通段间切换做成固定声音模板。
- `tick` 用于同一条数据流、标记组或节点组时，全组保持同一种音色；只有真实快闪或连续交接才允许 1–3 秒内短暂密集。
- `pop` 只给明确出现的卡片或 CTA 动作；`shimmer` 只给结果完成、规则锁定或价值揭示，不与同一时刻的其他长尾音效叠满。
- 五分钟左右的低动效知识口播片可先以约 30–45 个语义事件试配，但这不是硬上限。若锁定画面本身包含大量卡片序列、流程节点、路径绘制、点击与落位，允许按真实动作提高到约 100–130 个；不能为了守住低数字而让同一组相同动画有的响、有的不响。密度通过低增益、短尾音、同组声音家族和组级 Sweep 控制，而不是随机漏配。
- 口播存在时，短音效应“人耳可辨但不抢字”。完成混音后统一做节目级响度与真峰值控制，画面轨使用 `-c:v copy`，不得因音频调整再次压缩视频。

### 动作分类必须先于选素材

节目级混音也不能把所有动作粗略归成 `swish / tick / pop / shimmer` 后凭感觉撒点。必须先登记 `MotionSfxEvent`，按当前锁定画面的关键帧识别动作，再从下列职责中选择；没有明确动作就不登记事件：

- `UI_TICK`：小标签、列表节点依次出现；
- `DIGITAL_BLIP`：状态或图标由暗转亮；
- `UI_SNAP`：点击、锁定、吸附、落位、确认；
- `DIGITAL_SWEEP`：路径绘制、数据传递、面板持续展开；
- `MICRO_IMPACT`：章节内真正的核心结论或大数字重音；
- `SHORT_WHOOSH`：大于约 150 px 的快速位移或镜头级构图移动；
- `ERROR_BLIP`：错误、否定、失效或淘汰。

同类连续事件应轮换同一声音家族的变体，允许轻微音高差异，但不能换成完全不同质感。复合动作最多两层声音；普通字幕、轻微透明度变化、背景漂浮和无位移剪辑点保持无声。

### 同动作必须执行同一触发规则

- 同一条片中，相同组件、相同动画行为和相同语义角色必须使用同一 SFX 类别，并对齐到同一种关键帧。例如所有列表项都在“首次清晰可见”时触发 Tick，不能第一、二项有声而第三项无声。
- 若整组事件过密，只能采用明确且可复现的**组级替代**：例如同一路径上的连续数据粒子统一由一个 Sweep 承担；不能随机删掉其中几个 Tick。
- `appear → UI_TICK` 与 `arrive/confirm → UI_SNAP` 是不同语义角色，因此允许同样的卡片外形使用不同类别，但必须在事件表中写明角色差异。
- 每个事件至少登记：源组件或画面对象、绝对帧/时间、动作类别、SFX 类别和触发关键帧。密度上限只能在完成这张行为表之后决定。
- 所有风格共用这套行为逻辑；具体音色、尾音、明暗和质感可以按双色类、纯文案类或其他风格更换，但不能改变动作与声音职责的对应关系。

### 自带动效声区间必须建立排除窗

若锁定节目轨的某段已经含有可用动效声，应把完整区间登记为 `SFX_EXCLUSION_WINDOWS`，并在生成前校验任何新增事件都不落入该窗口。排除的是**所有新增 SFX**，不是只禁 BGM；区间边界还要覆盖前一个新增声音的尾巴，避免叠响。用户要求无 BGM 时，混音脚本不得加载音乐输入，也不保留旧的 BGM 派生版本冒充当前交付。

`SFX_EXCLUSION_WINDOWS` 必须写在对应片名、对应剪辑版本的混音脚本或项目登记中，不能进入全局默认值。只要片头、插入片、时间轴或静音策略发生变化，就必须重新检测该区间是否仍含源音效；旧片的绝对时间码禁止自动沿用到新版本或其他视频。

### 稀疏 BGM 岛

- BGM 不必贯穿全片；可从**同一首音乐**中裁取多个段落，按钩子、方法展开、总结等语义位置形成少量“音乐岛”。
- 每个音乐岛独立淡入淡出，音乐先做低高切和普通话存在频段让位，再由口播旁链压缩。
- 明确禁止 BGM 的区间必须在音乐时间轴中保持真实空白，不能只把音量压得很低。
- 同一条视频使用三段音乐岛时仍只算一首 BGM；不得用三首不同音乐冒充“分段配乐”。

## 规则一：多文字插入动画

### 适用场景

文字相关动画，涉及多条文字逐条插入。典型组件：
- [HighlightTag](./components/highlight-tag.md) 卡片依次弹出
- [StepList](./components/step-list.md) 步骤卡依次激活
- [StepFlowBar](./components/step-flow-bar.md) 节点依次点亮（带标签文字）

### 间隔 < 1s（30 帧）

**只能用 `tick` 或 `pop`，二选一，整组插入不能混用。**

例：4 张卡片间隔 0.7s 依次弹出 → 全部用 `pop`，或全部用 `tick`，不能前两张 pop 后两张 tick。

### 间隔 ≥ 1s（30 帧）

**`tick` / `pop` / `swish` 三选一，整组插入不能混用。**

例：3 张卡片间隔 2s 依次弹出 → 可全用 `pop`，或全用 `tick`，或全用 `swish`。不能混用。

### "同一处不能混用"的界定

- **同一组插入序列**（如同一行的卡片依次弹出、同一流程条节点依次点亮）= 同一处，必须用同一个音效
- **不同位置的插入序列**（如左上角标题区一组、底部流程条一组）= 不同处，可以分别选不同音效
- **同一段内**如果两个序列位置不同，可用不同音效（如 S2 卡片用 pop、流程条用 tick）

### 选择建议

无强制偏好，三种音效都符合规则时按场景氛围选：
- `pop`：卡片弹出感强，适合 HighlightTag 这类色块卡
- `tick`：轻巧短促，适合 StepFlowBar 节点点亮、StepList 步骤激活
- `swish`：稍长的"嘶"声，适合间隔较长（≥2s）的插入，避免短促音效落单显得突兀

## 规则二：答对/选对/做对

### 适用场景

视频中出现"正确选择"、"做对了"、"答对了"等肯定性瞬间。典型场景：
- 选择题答对
- 操作做对
- AI 生成结果符合预期（"对了"瞬间）

### 用法

```tsx
<HighlightTag
  text="答对了"
  sfxSrc={SFX.shimmer}
  ...
/>
```

`shimmer` 是"叮+闪烁"的复合音感，匹配"做对了"的肯定氛围。

### 本片应用

第 5 段“AI 生成结果”计数到 3 时代表结果完成，触发一次 `shimmer`。它与标题入场错开，避免多个提示音叠在同一时刻。

## 规则三：不使用的音效

### `swoosh`

历史用于 GlowTitle 标题滑入。当前规则下：
- GlowTitle 是**单条文字**插入，不属于"多文字插入"场景
- 单条文字插入不在本规则覆盖范围内，**默认无声**
- 因此所有 GlowTitle 调用不传 `sfxSrc`

### `ding`

历史用于 HighlightBox 脉冲强调。当前规则下：
- HighlightBox 是**框选区域**，不属于"文字插入"
- 框选出现/脉冲不在本规则覆盖范围内，**默认无声**
- 因此所有 HighlightBox 调用不传 `sfxSrc` 和 `pulseSfxSrc`

### 段间转场 swish

历史用于段末 6 帧淡出做"段落切换"信号。当前规则下：
- 段间转场不属于"文字插入"也不属于"答对"
- `swish` 仅用于多文字插入间隔 >1s 的场景
- 因此**删除所有段间转场 swish** 调用

## 段代码自查清单

写新段时按以下顺序检查音效配置：

1. **列出所有"多文字插入"序列**：哪些组件在本段会依次出现多条文字（HighlightTag/StepList/StepFlowBar）
2. **算每组序列的间隔**：相邻两次插入的帧差 / 30 = 间隔秒数
3. **按规则一选音效**：
   - 间隔 < 1s → `tick` 或 `pop`，全组统一
   - 间隔 ≥ 1s → `tick` / `pop` / `swish`，全组统一
4. **检查"答对"场景**：本段是否有"做对了"瞬间？有则用 `shimmer`
5. **禁止项自查**：
   - GlowTitle 不传 sfxSrc
   - HighlightBox 不传 sfxSrc / pulseSfxSrc
   - 不写段间转场 swish Sequence
6. **跨段一致性**：同一种"插入模式"（如步骤卡序列）在不同段建议用同一种音效，保持整片听感一致

## 触发时机（组件内部）

所有支持 sfxSrc 的组件，音效触发帧为 **视觉"出现"帧**：

| 组件 | 触发帧 | 说明 |
| --- | --- | --- |
| HighlightTag | `delay + Math.floor(enterDuration / 2)` | spring scale 达到峰值（1.15）的瞬间 |
| StepList | `step.enterFrame + Math.floor(enterDuration / 2)` | 同 HighlightTag |
| StepFlowBar | `step.activeFrame` | 节点点亮瞬间 |

详见各组件文档的"音效 prop"章节。

## 修改流程

如果规则变化（如新增可用音效、调整间隔阈值）：

1. 修改本文档
2. 仅变更公共默认音色时修改 `theme.ts` 的 `SFX` 常量；普通用户资产用 catalog ID 引用，不扩大默认常量
3. 新音效按[资产入库规则](./user-sfx-assets.md)写入共享 `public/sfx/` 与 catalog；用户音效不再向文档目录复制第二份
4. 仅检查受影响的组件或当前片事件，调整 sfxSrc / 事件配置；新增用户资产不自动改全库默认音色
5. 更新组件文档的"音效 prop"章节（如果有变化）
