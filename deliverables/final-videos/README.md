# 正式交付包

本目录是全仓库唯一的正式交付出口。根层只放本说明和按「片名-风格名」命名的目录；同片不同风格必须分开。

```text
final-videos/
└─ <片名>-<风格名>/
   ├─ <片名>-<风格名>-成片.mp4
   ├─ <片名>-<风格名>-封面-3x4.png  # 1080×1440，发布资料阶段生成
   ├─ <片名>-<风格名>-封面-4x3.png  # 1440×1080，发布资料阶段生成
   └─ 发布资料.docx                # 与封面同阶段生成
```

- 包内不再建任何子目录。完成成片时只要求有 MP4；用户明确提出“发布资料”后才制作或核验两张独立封面 PNG 及该风格的一份 DOCX。DOCX 只放一份通用发布标题、一份不超过 50 字的通用发布配文、一组在抖音核验的通用话题标签；所有平台使用同一组。封面和视频不写进 DOCX。
- 不放分段、半成片、短审片、验证文件、音频、字幕或 `v2/v003` 轮次副本。过程产物保存在 `remotion-clone/review/workflow-flash/<片名>/`。
- 发布前核对同片的所有风格目录与 `project.json.finalVideoVariants`。只有同风格修订版验收后才可覆盖其稳定文件；不同风格不得互相覆盖。
- 旧片已按片名和风格分包。没有收到“发布资料”请求时，缺封面或 DOCX 不影响成片阶段完成；收到请求后不能用未经确认的审片图或未经核实的文案冒充正式资料。

标题、文案和标签的选题与验证方法见 `docs/delivery-copy-and-tags.md`。
