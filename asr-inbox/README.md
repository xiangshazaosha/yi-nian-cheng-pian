# 原素材 ASR 转写固定入口

每份原素材使用 `asr-inbox/<原视频完整文件名>/`，文件名包含扩展名。先执行 `asr:init` 建立源文件指纹与仓库内只读用途副本。只在转写／剪辑需要时读取本目录，不默认加载其他素材的字幕。

多文件同片任务可按 `asr-inbox/<片名>/<原视频完整文件名>/` 分组，避免各批次 `1.MP4` 重名。当前灯塔口播使用此分组保存 ChatCut 原始微秒词级 JSON、只读原始 Script 与实际全文件哈希记录，直接引用用户原素材，不为接收 ASR 再复制大文件。该组是词级 ASR 接收包，不冒充已经通过单源 `asr:accept` 的完整 SRT 包；没有 SRT 就不伪造 `original.srt` 或校正完成状态。

历史云端工程曾因重新授权不可访问时，旧产物及身份审计保留在该目录的 `history/<明确归档原因>/`；历史固定文件的来源保持不变；未来默认Desktop，不能覆盖旧原件伪装来源。归档不是删除，不因新账号能够看到其他工程就推定旧成果也属于它。

固定文件：

- `source.json`：源视频身份、相对素材路径与实际探测信息；工具生成，不手填时长。
- `original.srt`：ASR 生成的**完整、未剪辑原素材**字幕，默认由 ChatCut 导出，时间零点为原素材开头；已有原件及真实来源记录保留，不因默认通道变更而改写来源或覆盖。
- `original.txt`：从原 SRT 原文按序提取的文案副本，不摘要、去重或改写。
- `words.raw.json`：可选词级 JSON 原件。目前必须验证格式、时间单位、完整性与音频对齐，不能因文件存在就用于精细切点。
- `source-timing.json`：可选本地ASR／Desktop共用的内部原素材微秒文字片段，来源与细粒度适配见对应操作包；原token和偏移证据仍保留，不覆盖旧 `words.raw.json`。
- `word-timing-report.json`：词级核验记录。历史云端有原素材毫秒行，当前Desktop返回微秒行，两者不可混用；字幕 `read_captions` token 帧时间不能冒充原始词级毫秒。语音行和 `[... seconds silent]` 标记要区分，结构通过不等于独立音频抽查通过。
- `receipt.json`：导入校验记录；全素材范围是导出方声明，时长校验并不能证明没有漏识别。
- `corrected.srt`、`corrections.json`：按[字幕规则](../docs/workflows/subtitles.md)另存校正版与逐条依据；原件不可被校正覆盖。

本目录的 ASR 接收阶段只保存未剪原素材转写，不混入删改后的时间线；Desktop 后续 Script 剪辑与原生导出按剪映操作包执行。默认使用 ChatCut Desktop，云端MCP已移除；明确本地ASR可选，分流见[流水线第 1 节](../docs/workflows/video-editing.md#1-原素材转写固定入口)，具体读取 [ChatCut ASR](../docs/workflows/chatcut-asr.md)，不例行重复确认通道，不加载其他部署分支。ChatCut 若只能导出时间线字幕，仍须使用原片从 0 开始、完整长度、速度 1 的单源时间线及原语言字幕轨，不用搜索的局部结果拼凑完整转写。已有字幕先核验复用；明确要求重转写时，新结果与旧原件分别保留，不覆盖历史或伪造来源。

完整交接规则与命令见[最小剪辑流水线](../docs/workflows/video-editing.md)。SRT 可以先工作；词级 JSON 未验证不得拖延句级接口建立，也不得被假装验证成功。
